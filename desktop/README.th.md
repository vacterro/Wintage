# Wintage สำหรับแอปพลิเคชันเดสก์ท็อป

สคริปต์ผู้ใช้ทำธีมให้เว็บ ส่วนนี้ทำธีมให้โปรแกรมรอบ ๆ เว็บ จากพาเล็ตชุดเดียวกัน เพื่อให้เบราว์เซอร์และแอปไม่ขัดแย้งกันว่าสีทองเข้มคืออะไร

มีกฎข้อเดียวอยู่เบื้องหลังทุกการตัดสินใจที่นี่: **แอปพลิเคชันอัปเดตตัวเอง และการอัปเดตต้องไม่ทำอะไรพังอย่างเงียบ ๆ** ที่ใดที่เป้าหมายมีที่อยู่ในโปรไฟล์ของคุณเอง ธีมจะอยู่ตรงนั้นและรอดผ่านการอัปเดต ที่ใดที่ไม่มี ตัวติดตั้งถูกเขียนให้รันซ้ำได้ — และบอกเช่นนั้น แทนที่จะแสร้งว่ามันคงอยู่ถาวร

## GUI

ดับเบิลคลิก **`Wintage Installer.vbs`** ที่รากของ repo เพื่อเปิดโดยไม่มีหน้าต่างคอนโซล หรือรันตรงนี้เพื่อการวินิจฉัย:

```powershell
powershell -File desktop\WintageInstaller.ps1
```

รายการธีมพร้อมชิปสี เป้าหมายที่พบบนเครื่องนี้ พรีวิว Win95 สด และโทเคนสีทั้งยี่สิบเอ็ดตัวเป็นสวอตช์ที่แก้ไขได้ การแก้สวอตช์ใด ๆ จะฟอร์กพาเล็ตเป็น **Custom** แทนที่จะเปลี่ยนธีมที่จัดส่งใต้มือคุณ แผงทางขวาแสดงคอนทราสต์ WCAG สดสำหรับสามโทเคนที่บรรทุกข้อความ — พาเล็ตที่ FAIL ตรงนั้นถูกเกตการสร้างปฏิเสธอยู่แล้ว ดังนั้นเห็นก่อน Apply ดีกว่าหลังจากนั้น

เป้าหมายถูกแบ่งเป็นสองรายการที่เข้าถึงด้วยคีย์บอร์ดได้: **MY APPS** มีเครื่องมือ CodeNomad, WorkBuddy แบบพกพา/จากซอร์สทรี; **POPULAR APPS** มี Windows, OBS, เทอร์มินัล, เอดิเตอร์ และซอฟต์แวร์ที่ติดตั้งอื่น ๆ ALL/NONE และ Apply/Revert ทำงานข้ามทั้งสองรายการโดยไม่เปลี่ยนการจัดกลุ่ม

หน้าต่างสวมพาเล็ตที่มันกำลังจะติดตั้ง นั่นคือพรีวิวที่เร็วที่สุดที่มี และทำให้เครื่องมือสัตย์ซื่อ: พาเล็ตที่ทำให้หน้าต่างนี้อ่านไม่ออกก็จะอ่านไม่ออกอย่างเห็นได้ชัด

Apply เรียกออกไปที่ `install.ps1` มีโค้ดพาธเดียวที่ติดตั้งธีม ดังนั้น GUI จึงไม่สามารถเลื่อนลอยห่างจากบรรทัดคำสั่งได้

## บรรทัดคำสั่ง

```powershell
.\desktop\install.ps1                                  # มีอะไรที่นี่, อะไรถูกทำธีม, ด้วยพาเล็ตไหน
.\desktop\install.ps1 -Target freebuff -Palette klite  # หนึ่งแอป, หนึ่งพาเล็ต
.\desktop\install.ps1 -Target all -Palette goldendefault # ทุกอย่าง
.\desktop\install.ps1 -Target all -WhatIf              # บอกว่าจะเปลี่ยนอะไร, ไม่แตะอะไรเลย
.\desktop\install.ps1 -Target freebuff -Revert         # เลิกทำหนึ่งตัว
```

`-Palette` ค่าเริ่มต้นคือ `goldendefault` (**Golden Default**) GUI เปิดที่พาเล็ตเดียวกันและตรวจทุกเป้าหมายที่มี การทาสีแอปที่ทำธีมแล้วซ้ำทำงานได้ในขณะที่มันรันอยู่; การติดตั้งครั้งแรกไม่ได้ เพราะไฟล์เก็บถาวรถูกใช้อยู่

### การลบโฆษณา FreeBuff

FreeBuff (แอปเดสก์ท็อปผู้ช่วย AI) จัดส่งเครือข่ายโฆษณาของตัวเอง: บันเดิลเรนเดอร์ (`resources/orchestrator/ui/assets/index-*.js`) เรนเดอร์การ์ด `sponsored-ad` และแบนเนอร์เธรด และ orchestrator (`resources/orchestrator/orchestrator.js`) เปิดเผยเส้นทาง `/api/ad/slot|impression|click` ที่เรียกการประมูลโฆษณาระยะไกล shim แค่ทำธีมแอป; มันไม่แตะไฟล์เหล่านั้น

`desktop/patch-freebuff-ads.js` ตัดโฆษณาออกที่ระดับไบต์:

- เรนเดอร์: จุดเรียกการ์ด/แบนเนอร์โฆษณากลายเป็น `null` และเมธอด API client `adSlot` / `adImpression` / `adClick` กลายเป็น no-op — ไม่มีอะไรเรนเดอร์ และไม่มีคำขอ `/api/ad/*` ใดออกจากเรนเดอร์;
- orchestrator: เส้นทาง `/api/ad/*` ทั้งสามหยุดเรียกเครือข่ายโฆษณา และคำขอโฆษณา inline ในเทิร์นสด (`maybeRequestAd`) ถูก short-circuit

ชื่อไฟล์บันเดิลฝังแฮชบิลด์ ดังนั้นแพตช์ค้นพบบันเดิลปัจจุบันจาก `index.html` แทนที่จะจัดส่งเพย์โหลดที่ล็อกเวอร์ชัน — นั่นคือสิ่งที่ทำให้มันรอดผ่านการอัปเดต ไฟล์ต้นฉบับถูกสำรองไปที่ `_orig-backup-<timestamp>/` ในไดเรกทอรีติดตั้ง; `--revert` คืนค่าอันล่าสุด

**เวอร์ชันอนาคตถูกจัดการที่สองเลเยอร์อิสระ:**

1. **Byte patch พร้อมฟอลแบ็ก regex.** ทุกเป้าหมายมีสตริงแม่นยำสำหรับบิลด์ปัจจุบัน *และ* ฟอลแบ็กนิพจน์ปกติที่ยึดกับสิ่งที่มินิไฟเออร์ไม่สามารถเปลี่ยนชื่อได้ — ตัวอักษรพาธ `/api/ad/*`, ตัวแยกโปรโตคอล `case"ad":`, คลาส `sponsored-ad`, และตำแหน่ง `variant:"banner"` / `variant:"card"` orchestrator ไม่ถูกมินิไฟ (ชื่ออ่านได้เช่น `maybeRequestAd` และ `app.ads.slotAd`) ดังนั้นสตริงแม่นยำของมันคงอยู่ได้นาน; บันเดิลเรนเดอร์ถูกมินิไฟ ดังนั้นฟอลแบ็ก regex ของมันเข้าควบคุมทันทีที่บิลด์ถัดไปเปลี่ยนชื่อตัวระบุ
2. **การบล็อกระดับ shim (`targets/electron/shim.cjs`).** เป็นอิสระจากบันเดิลโดยสิ้นเชิง: fetch/XHR ใด ๆ ไปยัง URL `/api/ad/` ถูกปฏิเสธภายในหน้า และองค์ประกอบใด ๆ ที่คลาสมี `sponsored-ad` ถูกซ่อนทันทีที่มันปรากฏ แม้บันเดิลใหม่เอี่ยมที่สคริปต์นี้ยังไม่เรียนรู้ก็ไม่สามารถโชว์โฆษณาได้

```powershell
node .\desktop\patch-freebuff-ads.js           # patch (สำรองก่อนเสมอ)
node .\desktop\patch-freebuff-ads.js --sound "C:\...\my.mp3"   # patch + เสียงเสร็จสิ้นกำหนดเอง (wav/mp3/ogg/flac/m4a/aac)
node .\desktop\patch-freebuff-ads.js --scan    # บิลด์นี้มีมาร์กเกอร์โฆษณาอะไรบ้าง?
node .\desktop\patch-freebuff-ads.js --verify
node .\desktop\patch-freebuff-ads.js --revert
```

มันรันอัตโนมัติเป็นส่วนหนึ่งของ `install.ps1 -Target freebuff` และต้องรันซ้ำหลังทุกอัปเดต FreeBuff (การอัปเดตคืนค่าไฟล์สต็อก) หากบิลด์เปลี่ยนรูปร่าง สคริปต์จะบอกชื่อเป้าหมายที่ไม่ตรงอีกต่อไป — รัน `--scan` เพื่อดูว่าบิลด์ใหม่ยังมีอะไรอยู่และรีเฟรชสตริงที่นั่น

**เสียงเสร็จสิ้น FreeBuff.** เรนเดอร์เล่น `chime-<hash>.mp3` เมื่อเทิร์นจบ แพตช์ค้นมันด้วยวิธีเดียวกับที่ค้นบันเดิล (ชื่อฝังแฮชบิลด์) ดังนั้น `--sound <file>` ติดตั้งเสียงของคุณเอง (wav/mp3/ogg/flac/m4a/aac) ทับมันและเก็บไฟล์สต็อกเป็น `chime-*.mp3.bak`; `--revert` คืนมัน `--verify` รายงานว่าอันไหนกำลังใช้งาน

### ปุ่มเสียง FreeBuff (GUI)

`WintageInstaller.ps1` มีปุ่มเล็ก **FB SOUND** ใต้สแต็ก APPLY / REVERT มันแค่เก็บ *ความชอบ*; `install.ps1 -Target freebuff` อ่านไฟล์เดียวกันแล้วส่งให้แพตช์เป็น `--sound` ดังนั้นโฆษณาและเสียงถูกใช้ในรันเดียว:

- **คลิกซ้าย** — เลือกไฟล์เสียง (OpenFileDialog, wav/mp3/ogg/flac/m4a/aac) และได้ยินมันเล่นทันที: PCM WAV ผ่าน System.Media.SoundPlayer, รูปแบบอื่นทุกแบบผ่าน WPF MediaPlayer (Media Foundation, แบบ async, หน้าต่างจึงไม่ค้าง) ตัวเลือกถูกจำไว้ใน `%APPDATA%\Wintage\freebuff-sound.txt` (ต่อเครื่อง, นอก git checkout, เหมือนกับโฟลเดอร์ซอร์สทรีที่จำไว้)
- **คลิกขวา** — ล้างความชอบกลับเป็นเสียง chime สต็อกของ FreeBuff (และหยุดพรีวิวใด ๆ ที่ยังเล่นอยู่)
- **COPY** — คัดลอกเสียงที่เลือกเข้า repo เอง (`sounds\freebuff.<ext>`, เก็บนามสกุลต้นทาง) และชี้ความชอบไปที่สำเนานั้น เสียงจึงรอดแม้ไฟล์ต้นฉบับถูกลบหรือย้าย เปิดใช้งานเฉพาะเมื่อตั้งเสียงกำหนดเอง; การคัดลอกซ้ำเพียงเขียนทับสำเนาใน repo โฟลเดอร์ `sounds/` เป็นเนื้อหาที่ git ติดตามได้ธรรมดา การ commit มันทำให้เสียงรอดผ่านการ clone ใหม่ด้วย

เฉพาะคอนเทนเนอร์เสียงที่รู้จักเท่านั้นที่ถูกพรีวิว — ส่วนหัวถูกสแกนก่อน ดังนั้นการเลือกที่ไม่ใช่เสียงจะถูกประกาศแทนที่จะเล่นอะไรเงียบ ๆ

ปุ่มอ่านค่า `ON` ในขณะที่ตั้งเสียงกำหนดเอง; การโฮเวอร์มันจะแสดงพาธ ใช้เป้าหมาย `freebuff` ทีหลัง (ติ๊ก FreeBuff + APPLY หรือรัน `install.ps1 -Target freebuff` จากเทอร์มินัล) เพื่อให้มันมีผล

### เทอร์มินัล

`terminal` เขียนโครงการสี `Wintage` ลงในทุกไฟล์การตั้งค่า Windows Terminal ที่ตรวจพบทั้งแบบ stable, Preview หรือแบบไม่แพ็ก และเลือกมันผ่าน `profiles.defaults` พร้อมกับ Consolas 12 ที่ปลอดภัยคอนโซลและข้อความ aliased ไฟล์ต้นฉบับถูกเก็บไว้ข้าง ๆ แบบไบต์ต่อไบต์ และ `-Revert` คืนมัน

`conhost` ครอบคลุม `cmd.exe` คลาสสิก, Windows PowerShell, โปรไฟล์คอนโซล Git CMD/Bash และลูก ๆ `HKCU\Console` ที่มีอยู่ มันเขียนตาราง 16 สีเต็มของพาเล็ตทั้งที่ค่าเริ่มต้นรากและทุกโอเวอร์ไรด์ที่มีอยู่ แล้วคืนเฉพาะค่าที่มันแตะ มันใช้ Consolas ตรงนั้นด้วย เพราะ Verdana แบบสัดส่วนชนกันในกริดเซลล์ความกว้างคงที่ที่โฮสต์เทอร์มินัลทั้งสองใช้

### เบราว์เซอร์และ Tampermonkey

`browsers` หาโปรไฟล์ Chrome, Edge, Brave, Cent, Vivaldi และ Opera จากตำแหน่งที่ติดตั้งและจากรากพกพาที่คุณชี้ให้มัน (`-PortableRoot`, หรือรายการ `portable` ที่จำไว้ใน `paths.json`) สถานะของมันแสดงทั้งจำนวนโปรไฟล์และจำนวนที่มี Tampermonkey Apply คัดลอกธีมเบราว์เซอร์ที่เลือกไปยังโฟลเดอร์คงที่ `%LOCALAPPDATA%\Wintage\browser-theme`, วางพาธนั้นบนคลิปบอร์ด และเปิดแต่ละโปรไฟล์ตรง ๆ ที่ `chrome://extensions` พร้อมกับหน้า Install/Update สคริปต์ผู้ใช้ Wintage โปรไฟล์ที่ไม่มี Tampermonkey ยังได้หน้า Chrome Web Store ของมัน

Chromium จงใจห้ามการติดตั้งเอ็กซ์เทนชันนอกสโตร์แบบเงียบ ๆ บนเครื่อง Windows ที่ไม่มีการจัดการ ดังนั้นการติดตั้งธีมเบราว์เซอร์ครั้งแรกจึงต้องการการยืนยัน **Developer mode → Load unpacked** หนึ่งครั้งต่อโปรไฟล์ เลือกพาธที่คัดลอก; หลังจากนั้น Wintage จะแทนที่โฟลเดอร์คงที่เดียวกันต่อไปเมื่อพาเล็ตเปลี่ยน ยืนยัน **Install/Update** ใน Tampermonkey ด้วย ไม่มีการแก้ไฟล์ `Preferences`, Secure Preferences หรือ LevelDB ของ Tampermonkey ใด ๆ ลับหลังเบราว์เซอร์ หากไม่มี Tampermonkey ให้ติดตั้งจากแท็บสโตร์ที่เปิด และรีเฟรชแท็บ `wintage.user.js` ที่เปิดอยู่แล้วเพื่อให้ได้หน้าติดตั้ง

### Windows

`windows` ติดตั้งและเปิดใช้งานทันทีธีมแบบ content-addressed `%LOCALAPPDATA%\Microsoft\Windows\Themes\Wintage-<hash>.theme` มันเริ่มจากธีมที่ใช้งานและแทนที่เฉพาะส่วนสี เคอร์เซอร์ และสไตล์ภาพที่บันทึกไว้ วอลเปเปอร์ เสียง และไอคอนเดสก์ท็อปยังคงเดิม; เคอร์เซอร์ตั้งใจสลับเป็นโครงการ `___CURRENT___` ที่ติดตั้ง ธีมแรกที่ใช้งานถูกบันทึกแบบไบต์ต่อไบต์เป็น `Wintage.original.theme`; การเปลี่ยนพาเล็ตคงเส้นฐานนั้น และ `-Revert` เปิดใช้งานมันอีกครั้ง คอนโทรล Windows สมัยใหม่ยังมาจากสไตล์ภาพ Aero ที่เซ็นชื่อ — Wintage เปลี่ยนโหมดมืด accent และอินพุตสีระบบคลาสสิกที่รองรับของมัน แทนที่จะแทนที่ไฟล์ `.msstyles` ที่ถูกป้องกัน ส่วนหัวแบบ active และ inactive ใช้สีพื้นผิวนูนแบบ muted ของพาเล็ตร่วมกัน; ไฮไลต์สว่างสงวนไว้สำหรับขอบข้อความ/การเลือก ค่า accent ส่วนหัว inactive ก่อนหน้านี้ถูกสแนปชอตแยกและคืนค่าแม่นยำโดย `-Revert` แฮชเนื้อหาให้ Windows ได้เป้าหมายการเชื่อมโยงไฟล์ใหม่เมื่อพาเล็ตเดียวกันถูกสร้างใหม่ การใช้พาเล็ตที่อัปเดตซ้ำจึงไม่ถูกเข้าใจผิดว่าเป็น no-op; ไฟล์ Wintage ที่ถูกแทนที่จะถูกลบหลังจาก Windows ยืนยันว่าไฟล์ใหม่ active แล้ว

### OBS Studio

`obs` สร้างวาเรียนต์ OBS 30.2+ ทับฐาน Yami Classic ที่ดูแลอยู่ ติดตั้งลง `%APPDATA%\obs-studio\themes` และเขียนไอดีธีมคงที่ลง `user.ini` พาเล็ต Wintage ที่เลือกจึงถูกเลือกไว้แล้วในการเปิดครั้งถัดไป ปิด OBS ก่อน Apply หรือ Revert: OBS เขียน `user.ini` ใหม่ตอนปิด การ apply ครั้งแรกสำรองทั้งการเลือกก่อนหน้าและธีมชื่อเดียวกันแบบไบต์ต่อไบต์

### qBittorrent

`qbittorrent` เขียนธีม UI ของ Qt **แบบไม่แพ็ก** ลงใน `%APPDATA%\qBittorrent\themes\wintage` — ไฟล์ `config.json` (บทบาท `Palette.*` บวกสีบริบทของ qBittorrent เอง: สถานะของรายการถ่ายโอน ความรุนแรงของบันทึก) และ `stylesheet.qss` ข้าง ๆ กัน (ขอบเอียง 2px มุมฉาก และ Verdana ซึ่งพาเลตต์แสดงออกไม่ได้) — จากนั้นชี้ `General\CustomUIThemePath` ไปที่ `config.json` นั้นและตั้ง `General\UseCustomUITheme=true`
ตั้งใจใช้แบบไม่แพ็กแทนบันเดิล `.qbtheme`: ไฟล์ `.qbtheme` เป็นไฟล์ Qt Resource Collection และต้องใช้ไบนารี `rcc` เวอร์ชันหลักที่ตรงกันบนเครื่องเพื่อสร้าง ซึ่งกลายเป็นการพึ่งพาตัวคอมไพเลอร์เพียงเพื่อไฟล์ข้อความสองไฟล์ ส่วน qBittorrent อ่านรูปแบบโฟลเดอร์ได้เองโดยตรง (`FolderThemeSource`)
ปิด qBittorrent ก่อนกด Apply หรือ Revert: มันเขียน `qBittorrent.ini` ใหม่ทั้งไฟล์ตอนปิด การแก้ไขที่ทำขณะมันทำงานจึงถูกทิ้งตอนปิด — เป้านี้จึงปฏิเสธที่จะทำงานในสภาพนั้น แทนที่จะรายงานความสำเร็จที่การปิดครั้งถัดไปลบทิ้ง `-Revert` คืนค่าคีย์ INI สองคีย์กลับเป็นค่าเดิมก่อน Wintage อย่างแม่นยำ (หรือลบทิ้งถ้าเดิมไม่มี) และวางโฟลเดอร์ธีมชื่อเดียวกันกลับแบบไบต์ต่อไบต์ ส่วนการแก้ไข `qBittorrent.ini` อื่น ๆ ที่ทำหลัง Apply จะอยู่ต่อ
ไปไม่ถึง: ไอคอนบนแถบเครื่องมือและถาดระบบมาจากชุดทรัพยากรที่คอมไพล์ไว้ของ qBittorrent เอง จึงคงสีเดิมไว้

### แบบอักษร: มีชื่อเรียก แต่ไม่เคยถูกติดตั้ง

กฎข้อ 1 ใน UI.md เรียกร้อง Verdana **โดยไม่มีการลบรอยหยัก (antialiasing)** แชสชีตของ Qt ไม่มีคุณสมบัติที่ทำเช่นนั้น และ `OSDFont` ของ MPC-HC ก็เป็นเพียงชื่อแบบอักษร GDI ธรรมดา ดังนั้นคันโยกเดียวที่มีผลคือตัวแบบอักษรเอง ไฟล์ `Verdana_m1.ttf` ที่รากของรีโพเป็นสำเนาของ Verdana ที่พกภาพบิตแมป 1bpp ซึ่งเรนเดอร์ไว้ล่วงหน้าตั้งแต่ 3 ถึง 30 ppem ซึ่งเรนเดอร์จะเลือกใช้แทนการเกลี่ยเส้นขอบ
แชสชีตของ `qbittorrent` และ `obs` ระบุ `Verdana_m1, Verdana` ส่วน `mpchc` ระบุตัวที่เครื่องแก้จริงเป็นตัวที่ถูกเลือก **ตัวติดตั้งไม่เคยติดตั้งหรือถอนแบบอักษรออกเลย** และนั่นเป็นการตัดสินใจอย่างตั้งใจ ไม่ใช่งานที่ทำค้างไว้:
การเลือกใช้แบบอักษรทำตามคู่ (ตระกูล รูปแบบ) หากลงทะเบียน Regular + Bold + Italic ผู้ใช้ทุกรายจะเลือกได้ถูกต้อง แต่ถ้า **ถอด** สมาชิกเพียงตัวเดียว ผู้ใช้ทุกรายที่ขอตระกูลนั้นจะถูกส่งต่อไปยังสมาชิกที่ยังอยู่ บนเครื่องที่ผูก `MS Shell Dlg 2` ซึ่งเป็นแบบอักษรของกล่องโต้ตอบของ Windows ให้ชี้ไปที่ตระกูลนั้นผ่าน `HKLM\...\FontSubstitutes` การถอด Regular ออกจะทำให้ **เดสก์ท็อปทั้งเครื่องเป็นตัวเอียง** รวมถึงชื่อหน้าต่างที่ DWM แคชไว้แล้ว และต้องออกจากระบบเพื่อให้กลับมาได้ ไม่มีการนับการอ้างอิงใดแก้ได้ เพราะขอบเขตความเสียหายครอบคลุมทั้งเครื่อง และตัวติดตั้งธีมไม่ควรไปยุ่งตรงนั้น
ดังนั้นแบบอักษรนี้เป็นการกระทำของผู้ใช้ที่ชัดเจนเพียงครั้งเดียว คลิกขวาที่ `Verdana_m1.ttf` แล้วเลือก **ติดตั้ง** (ต่อผู้ใช้ ไม่ต้องใช้สิทธิ์ผู้ดูแลระบบ) จากนั้นจึงใช้เป้าหมายอีกครั้ง หากไม่มีแบบอักษรนั้น เป้าหมายจะบอกเพียงครั้งเดียว เอ่ยชื่อทางแก้ไข แล้วถอยกลับไปใช้ Verdana ดั้งเดิม ซึ่งมี antialiasing แต่ไม่มีการแก้ไขเครื่องของคุณลับหลัง

### แอป Electron

`resources/app.asar` ถูกย้ายไปเป็น `resources/app/app.asar` (พี่น้อง `app.asar.unpacked` ย้ายไปด้วย — การจับคู่นั้นอิงชื่อไฟล์ และการแยกมันทำลายโมดูลเนทีฟทุกตัว) และ `shim.cjs` เล็ก ๆ เข้าครอบตำแหน่ง `resources/app` ที่ว่าง shim ฉีดสไตล์ชีตแล้วโหลดถาวรต้นฉบับ **ไม่มีไบต์แอปใดถูกเขียนใหม่**, แค่ย้ายตำแหน่ง; `-Revert` ย้ายกลับทันที

สไตล์ชีตไม่ได้ถูกเขียนสำหรับแอปเหล่านี้ — มันถูกสกัดจาก `wintage.user.js` ทุกการแก้ไขขอบ สกรอลล์บาร์ และลำดับแบบอักษรที่ทำเพื่อเบราว์เซอร์จึงมาถึงที่นี่ด้วย ไม่มีสำเนาที่สองให้เน่า

สองหมายเหตุที่คุ้มรู้ล่วงหน้า:

- วิธีที่เห็น ๆ — วาง `resources/app` ข้างถาวรและพึ่งว่า Electron จะชอบมัน — **ใช้ไม่ได้และล้มเหลวอย่างเงียบ ๆ** Electron ค้นหา `app.asar` ก่อน แอปเริ่มปกติสมบูรณ์และธีมไม่เคยรัน
- shim เป็น `.cjs`, ไม่ใช่ `.js`, โดยตั้งใจ `package.json` ของมันถูกคัดลอกจากของแอปเอง แอปจึงรักษาชื่อและเวอร์ชันไว้ (ชื่อตัดสินว่า userData อยู่ที่ไหน — shim ที่เปลี่ยนชื่อจะย้ายแอปไปยังโปรไฟล์ว่าง) ถ้าแถวแถลงนั้นบอก `"type": "module"` shim แบบ `.js` จะตายที่ `require` แรก

### แอปเดสก์ท็อปของ Claude: แบบในตำแหน่งเดิม และเฟรมที่มันวาดจริง

Claude ใช้การย้ายตำแหน่งข้างบนไม่ได้ เพราะ `OnlyLoadAppFromAsar` ถูกเปิดฟิวส์ทับ — Electron โหลด `resources/app.asar` อย่างเดียว shim ใน `resources/app` จึงรันไม่ได้เลย มันถูกแพตช์ **ในตำแหน่งเดิม** แทน: ถาวรถูกสำรอง `main` ใน `package.json` ถูกเขียนใหม่เป็น `"../wintage-shim.cjs"` (เสริมความยาวให้เท่าไบต์เดิม เพื่อให้ทุกออฟเซ็ตในถาวรยังใช้ได้) และแฮชความสมบูรณ์ต่อไฟล์ถูกอัปเดตให้ตรง `-Revert` คืนแบ็กอัป

ตัวติดตั้งยังอ่านฟิวส์ **ก่อนมันย้ายอะไร** และปฏิเสธพร้อมเหตุผลเมื่อมันขวาง — `EnableEmbeddedAsarIntegrityValidation` จะทำให้การเขียนใหม่ข้างบนล้มเหลวตอนเปิดแอป แทนที่จะตอนติดตั้ง ตรวจแอปใด ๆ ด้วยตัวเอง:

```powershell
node ..\tools\electron-fuses.js "<path to the app's exe>"
```

ครึ่งหลังของอันนี้เป็นปัญหาที่เงียบกว่ามาก `BrowserWindow` ของ Claude เรนเดอร์เปลือกบาง และ**แอปที่มองเห็นทั้งหมดเป็น `WebContentsView`** ที่แนบกับมัน shim เคยฮุค `browser-window-created` มันจึงฉีดสไตล์ชีตเข้าปลือก รายงานความสำเร็จไปที่ `wintage-status.txt` และไม่เปลี่ยนอะไรที่คุณเห็นได้ ตอนนี้มันฮุค `web-contents-created` ซึ่งครอบคลุมทั้งเนื้อหาหน้าต่าง `WebContentsView`, `BrowserView`, แขก `<webview>` และป็อปอัป

### Obsidian

ธีมคอมมูนิตี้ถูกเขียนลง `.obsidian/themes/` ของทุก vault — ทั้งสิบหกพาเล็ตพร้อมกัน เหมือนกับเป้าหมาย VS Code คุณจึงสลับระหว่างมันใน **Settings → Appearance** โดยไม่ต้องรันอะไรซ้ำ เทมเพลตได้มาจากธีม `VintageWin95` ทำมือที่อยู่ใน vault แล้ว สีทุกสีถูกแทนที่ด้วยโทเคนที่มันเท่ากับ `-Palette <slug>` กำหนดว่าอันไหน active ตอนติดตั้ง; `appearance.json` ถูกสำรองก่อน และ `-Revert` ลบเฉพาะธีม `Wintage *` และคืนตัวเลือกก่อนหน้าของคุณ — ธีมทำมือใน vault เดียวกันจะไม่ถูกแตะเลย


### MPC-HC (K-Lite)

Win32 เนทีฟ ไม่มีสไตล์ชีตและไม่มีจุดฉีด และสีธีมมืดของมันถูกคอมไพล์ในโปรแกรม — ไม่มีค่ารีจิสทรีเปิดเผยมัน เป้าหมายนี้จึง**ไม่สามารถบรรทุกพาเล็ตได้** สิ่งที่มันทำ: เปิดธีมมืดและใช้กฎการพิมพ์ของ UI.md กับ OSD ซึ่งเป็นพื้นผิวเดียวที่ MPC-HC ให้ผู้ใช้ควบคุม การตั้งค่าก่อนหน้านี้ถูกส่งออกไปที่ `desktop/backup/mpc-hc-settings.reg` ก่อน

ปิด MPC-HC ก่อน apply: มันเขียนการตั้งค่าใหม่ตอนปิด

## การสร้างใหม่

ทุกอย่างใต้ `desktop/out/` ถูกสร้างจาก `themes/*.json` มันไม่ถูกติดตามใน git (T-160) โคลนใหม่จึงต้องสร้างมันหนึ่งครั้งก่อนติดตั้ง:

```powershell
node ..\tools\build-desktop.js          # สร้างทุกเป้าหมายใหม่
node ..\tools\build-desktop.js --check  # exit 1 ถ้ามีอะไรล้าสมัย
```

`release.ps1` รันการสร้างและทุกเกต การปล่อยรุ่นจึงไม่สามารถจัดส่งเอาต์พุตที่เลื่อนลอยจากพาเล็ตได้

## ความครอบคลุมของเป้าหมายและหัวข้อ

หัวข้อนี้สะท้อนความครอบคลุมของ Process Explorer, Notepad++, Cinema 4D และฟอนต์เทอร์มินัล ตาม README ภาษาอังกฤษฉบับปัจจุบัน เพื่อไม่ให้คำแปลนี้ค้างเก่าโดยเงียบ ๆ ตัวอักษรในโค้ด (id ของเป้าหมาย พาธของรีจิสทรี ชื่อไฟล์) ไม่ขึ้นกับภาษาโดยตั้งใจ ส่วนข้อความรอบ ๆ เหล่านั้นแปลไว้แล้ว

### แต่ละเป้าหมายทำธีมได้จริงอะไรบ้าง (เป้าหมายที่เพิ่มเข้ามา)

| เป้าหมาย | กลไก | รอดการอัปเดตของแอปหรือไม่ |
|---|---|---|
| `notepadplusplus` | XML ธีม + alias เข้าไปในโฟลเดอร์ `themes` ของ Notepad++ ของคุณ | ใช่ — มันอยู่ในโปรไฟล์ของคุณ |
| `cinema4d` | ชุดสีที่วางลงในโฟลเดอร์ `schemes` ของ Cinema 4D ของคุณ | ใช่ — มันอยู่ในโปรไฟล์ของคุณ |
| `processexplorer` | `HKCU\Software\Sysinternals\Process Explorer`: สีไฮไลต์แถวและพื้นหลังกราฟ ดูด้านล่าง | ไม่ — Process Explorer เขียนการตั้งค่าของมันใหม่ตอนออก ปิดมันแล้วรันใหม่ |

### Process Explorer (Sysinternals)

Process Explorer เก็บสีของมันไว้ที่ `HKCU\Software\Sysinternals\Process Explorer` และเขียนคีย์นั้นใหม่ตอนออกจากโปรแกรม เป้าหมายนี้จึง **ปฏิเสธขณะที่ `procexp`, `procexp64` หรือ `procexp64a` ยังทำงานอยู่** — ปิดมันแล้วรันใหม่ มันทำธีมให้หมวดสีที่ตั้งค่าได้เหล่านี้:

- **เข้าถึงได้**: สีไฮไลต์แถวของกระบวนการ (`ColorOwn`, `ColorServices`, `ColorRelocatedDlls`, `ColorImmersive`, `ColorPacked`, `ColorJobs`, `ColorNet`, `ColorProtected`, `ColorNewProc`, `ColorDelProc`, `ColorSuspend`) ทั้งในแบบโหมดสว่างและในแบบ `*Dark` ของแต่ละสี บวกกับพื้นหลังกราฟ (`ColorGraphBk`, `ColorGraphBkDark`) — รวม 24 ค่า แต่ละแบบถูกผสมไปหาขั้วเดียวกันของพาเล็ตที่ใช้งานอยู่ (เฉดอ่อนกว่าสำหรับสีเติมในโหมดสว่าง เฉดเข้มกว่าสำหรับ `*Dark`) สีเติมของแถวจึงยังอยู่ในเฉดของพาเล็ตนั้นเอง แทนที่จะซีดจนเกือบเป็นสีขาว
- **เข้าถึงไม่ได้**: แถบชื่อเรื่อง แถบเมนู แถบเครื่องมือ พื้นหลังและสีตัวอักษรในมุมมมรายการ รวมถึงสีเส้นกราฟ — สิ่งเหล่านี้ถูกคอมไพล์ไว้ใน `procexp.exe` และไม่มีค่าตั้งค่าใดเปิดเผยมัน เป้าหมายนี้ทำธีมให้เฉพาะไฮไลต์แถวและพื้นหลังกราฟที่มันเป็นเจ้าของจริง ๆ และไม่อ้างอะไรเกินกว่านั้น

ทุกค่าที่ Apply แก้ไขได้จะถูกบันทึกเป็นสแนปชอตก่อนแก้ (กู้คืนเมื่อแตะครั้งแรกที่ `%APPDATA%\Wintage\recovery\processexplorer\`) และถูกกู้คืนอย่างตรงเป๊ะโดย `-Revert` รวมถึงข้อเท็จจริงว่าค่านั้นไม่มีอยู่หรือไม่ และเครื่องหมายนั้นมีอยู่แต่ว่างหรือไม่ โฟลเดอร์แบบพกพาที่อยู่นอกไดเรกทอรีมาตรฐานของ Sysinternals จะถูกจดจำผ่านคีย์ `processexplorer` ใน `paths.json` (อาร์กิวเมนต์บรรทัดคำสั่ง `-ProcessExplorerPath`; ส่วน GUI เลือกให้ได้เช่นกัน)

### ฟอนต์เทอร์มินัล (`fonts/terminal/`)

เป้าหมายเทอร์มินัลทั้งสองอ่านค่ากำหนดตัวอักษรแบบบัญญัติเพียงค่าเดียวจาก `%APPDATA%\Wintage\terminal-font.json` (`schema`, `fontSlug`, `family`, `size`, `renderingMode`) เมื่อไม่มีไฟล์นี้ เป้าหมายจะยังคงค่าเริ่มต้นที่มาพร้อม (Terminus (TTF) for Windows, 12 pt, aliased) เครื่องที่ใช้อยู่เดิมจึงไม่เปลี่ยนแปลง ค่ากำหนดที่ผิดรูปแบบจะล้มเหลวแบบปิดสนิท: ไม่มีอะไรถูกเขียนทับ และเป้าหมายปฏิเสธ

`fonts/terminal/catalog.json` คือแคตตาล็อกฟอนต์ชุดเดียว: ตระกูลมอโนสเปซโอเพนซอร์สที่แถมมา 20 ตระกูล บวกกับฟอนต์ระบบสองตัวที่ Wintage เอ่ยชื่อแต่ไม่เคยแถมมา (Terminus (TTF) for Windows, Consolas) ทุกรายการที่แถมมาจะบรรทุกต้นทางอัปสตรีม รุ่นที่ตรึงไว้ id ของสัญญาอนุญาต ไฟล์สัญญาอนุญาต และ SHA-256 ไฟล์ต้นฉบับอยู่ใต้ `fonts/terminal/files/` พร้อมข้อความสัญญาอนุญาตใต้ `licenses/`; ขณะรันอยู่ Wintage ทำงานแบบออฟไลน์ทั้งหมดและไม่เคยดาวน์โหลดฟอนต์เลย

`tools/sync-terminal-fonts.ps1` คือตัวดาวน์โหลดสำหรับผู้ดูแลระบบเท่านั้น มันอ่าน `fonts/terminal/sources.json` (หนึ่งอาร์ติแฟกต์ที่ไม่เปลี่ยนแปลงต่อหนึ่งตระกูล) ตรวจสอบ SHA-256 ทุกรายการ และปฏิเสธเมื่อไม่ตรงกัน `-VerifyOnly` (ค่าเริ่มต้น) ตรวจไฟล์บนดิสก์โดยไม่ใช้เครือข่าย ส่วน `-Fetch -Write` แจกไฟล์เข้าใหม่ ไบต์ของฟอนต์ที่ดาวน์โหลดมาถือเป็นทรัพยากรไบนารีที่ไม่น่าเชื่อถือ — คำนวณแฮชแล้วเขียนลงไป ไม่เคยถูกเรียกทำงาน มีการบันทึกการแทนที่หนึ่งรายการ: **Fantasque Sans Mono** แทนที่ Liberation Mono ซึ่งไม่เผยแพร่รุ่นไบนารีที่ตรึงไว้เลย (มีแต่ไฟล์ต้นฉบับ `.sfd`)

ตัวติดตั้ง **ค้นหาฟอนต์ ไม่ได้ติดตั้งฟอนต์** แท็บ TERMINAL FONTS โหลดฟอนต์ที่แถมมาเข้า `PrivateFontCollection` ที่อยู่เฉพาะกระบวนการเพื่อพรีวิวสด ซึ่งทำการ **ลงทะเบียนฟอนต์ระบบศูนย์ครั้ง** การเลือกฟอนต์ ขนาด (7–24 pt) หรือโหมดการเรนเดอร์ (aliased/grayscale/cleartype) อัปเดตเฉพาะพรีวิวและค่ากำหนด การติดตั้งฟอนต์เป็นการกระทำ **INSTALL SELECTED** โดยเฉพาะ ซึ่งเปิดตัวติดตั้งฟอนต์ของ Windows เอง เมื่อ Windows ยืนยันแล้ว ผู้ใช้สแกนหาค่าใหม่อีกครั้งด้วย Refresh การเปลี่ยนแปลงเทอร์มินัลจริงเกิดขึ้นเฉพาะเมื่อกระทำ **APPLY TERMINAL / APPLY CONHOST / APPLY BOTH** เท่านั้น

Windows Terminal ถูกใช้กับตระกูลที่ติดตั้งและเลือกไว้ในขนาดที่เลือกไว้ ส่วนโหมดการเรนเดอร์จับคู่กับ `profiles.defaults.antialiasingMode` ส่วน conhost แบบคลาสสิกเข้มงวดกว่า: มันเรนเดอร์บนตารางเซลล์ขนาดคงที่ เป้าหมายที่เลือกไว้จึงถูกปฏิเสธก่อนการแก้รีจิสทรีใด ๆ เว้นแต่ Windows จะหามาแทนได้ (ฟอนต์เริ่มต้นและตัวสำรอง Consolas ได้รับยกเว้น) Health และ Reapply จะตรวจสอบฟอนต์ ขนาด และการลบขอบที่ตั้งค่าไว้เทียบกับค่ากำหนด ดังนั้นการเปลี่ยนค่ากำหนดหลังจาก Apply จะถูกรายงานว่าเป็นความคลาดเคลื่อน ไม่ใช่ว่า "ปกติดี" วงจรชีวิตของสีเทอร์มินัลไม่ถูกแตะ: Revert คืนค่าที่ Wintage เป็นเจ้าของก่อนหน้านั้นได้อย่างตรงเป๊ะ และไม่เคยถอนฟอนต์ออกจากเครื่อง
