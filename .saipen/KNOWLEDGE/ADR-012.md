# ADR-012 — A release binds to the destination the clients poll, and proves the delivered artifact

Date: 2026-10-22. Tickets T-981, T-982, T-983, T-984 (improve cycle imp-vacuum34-wintage-20261022-1, RUN-1/IMP-001, IMP-002, IMP-003, IMP-004).

## Context

The distribution moved from `github.com/vacterro/Wintage` to
`gitlab.com/vacuum34/wintage` in release 1.36.10, and the ledger recorded the
GitHub side as dead: `E-4321` says `git ls-remote` answers `403 Your account is
suspended`, the raw URL answers `404`, and the repository page answers `404`.
That is false. `git ls-remote github` exits 0, the GitHub API reports the
repository as public, `archived: false`, pushed at `2026-10-21T04:14:25Z`, and
the operator's own repair `052f416` was committed on that side. Two live public
remotes now serve two different versions of the same product, and the
difference is invisible to every gate in this repository, because every gate
reads the working tree.

Two things went missing in that migration, and both are release safety, not
documentation.

First, the release never knew WHERE it published. It pushed to a remote named
`origin` and verified that the ref moved. The URL the browsers poll lives in
the installed script's own metadata, a different file entirely, and nothing
compared the two. A release could therefore report success while every client
kept the old build -- and because the poll URL is part of the installation, not
part of the repository, no later release could fix it either.

Second, the release never checked WHAT it published. It verified the pushed
ref, which is a fact about git, and then printed "Tampermonkey clients will
pick it up on their next update check" -- a claim about the artifact the
browser installs, which it never looked at. The project already owned the
detector for exactly that measurement, `tools/check-deployed-userscript.js`,
whose own header says the delivery path is "the one link they never touched" --
and it was invoked by no release step and by no test.

## Decision

A release names the destination it publishes to, and refuses to publish
anywhere else.

- `tools/check-release-target.js` compares the push target with the
  userscript's `@updateURL`/`@downloadURL`: same repository, same branch, same
  file. `release.ps1` runs it in the preflight, before anything is mutated, so
  a mismatch aborts with the tree untouched. The commit body records the
  destination (`Published to: <url>`), and the success line names it.
- `release.ps1` runs `tools/check-deployed-userscript.js` against the install
  URL after the push and reports a stale delivery instead of a green success
  line. A raw URL can lag behind a push, so the check is retried; an
  unreachable artifact is reported as UNPROVEN rather than as a pass.
- The detector keeps its network dependency. It is a RELEASE step, not a
  blocking suite gate: the suite exercises the same tool against a local
  fixture server (`tools/test-release-delivery.js`), so the deterministic suite
  stays offline and the release still measures the real thing.
- A user's own file is not redistribution content. The desktop installer no
  longer writes the picked FreeBuff sound into the checkout (`%APPDATA%` is
  the destination now, with the old in-repo path migrated on load), `sounds/`
  is gitignored, and the tracked game-derived wav is out of the tree.

## Consequences

- Two live remotes can no longer be a silent trap. Repointing `origin` at the
  wrong repository fails the release before it mutates anything, and a release
  that published to the wrong place is visible in the commit history.
- A release that pushed successfully but published an artifact nobody can fetch
  now says so. The cost is that a release can fail AFTER it published; the
  message says exactly that, because the alternative -- a green line over an
  unproven delivery -- is the defect this ADR exists to end.
- The release gate set grew from 18 derived tool steps to 20, and the suite
  runs both new tools. `tests/test-release-gate-audit.ps1` pins the count, so
  dropping either gate is loud.
- A ledger line that is factually wrong is corrected, not carried forward: the
  1.36.10 changelog entry and `E-4321`'s "dead remote" claim are both wrong
  about the world, and a project that publishes "the repository is gone" while
  it is alive sends its users chasing a phantom outage.
