# ADR-003 — Applying UI.md to arbitrary websites: what was taken literally, and what was not

Status: ACCEPTED (26.07.26, shipped v1.4.0)
Related: [[ADR-001]] (animation taming), [[ADR-002]] (sweeper read/write split)

## Context

Goal: make every site look as much alike as possible, per
`V:\___VAC\__K\__CODE\_AI_STUFF_AGENTIC\_SAIPEN\saipen\UI.md`.

UI.md is written for **building** an interface, where the author controls every
margin and every colour. This theme **retrofits** it onto sites that were built
by someone else and are actively fighting back with their own `!important` rules.
Most of UI.md transfers directly. A few rules do not, and the difference matters
enough to write down — otherwise the next pass "fixes" the gaps and breaks real
pages.

## Applied literally

| UI.md rule | How |
|---|---|
| Law 3, depth is **2px bevel only** | `B_OUTER`/`B_INNER` rewritten to UI.md's exact 4-value `border-color` form. The old bevel was 1px borders + an inset `box-shadow`, breaking laws 2 and 3 at once. |
| Law 2, **zero shadow** | Global `box-shadow: none` / `text-shadow: none` on `*, *::before, *::after`. Nothing of ours is lost since the bevels are pure borders now. |
| Law 2, **zero blur** | Global `backdrop-filter: none`. `filter: none` too, but NOT on `img/svg/video/canvas/picture` — sites legitimately recolour icons with `filter`, and a blanket kill leaves white-on-white icons invisible. |
| Law 2, **zero gradients** | Moved into the JS repainter and widened from light-only to ALL gradient hues. |
| Law 1 + typography, **10/11/12/14/16px only** | 12px body, `h1` 16px, `h2..h6` 14px, `small/sub/sup/figcaption` 10px, `line-height: 1.2`. |
| Law 5, **token-only colour** | Full UI.md token block in `:root`; a `T` object is the only place this file may emit a colour from. Verified: 0 off-palette backgrounds and 0 off-palette text colours across 16921 live elements. |
| Accessibility floor | Focus outline widened to every focusable control (the global shadow kill removed the ring sites draw with `box-shadow`, so this outline is now the only focus affordance). Button `min-width: 24px` / `min-height: 20px`. |
| Disabled controls | `--textMuted` label on the same raised surface, `opacity: 1` forced. UI.md bans `opacity` here twice over: law 2 bans transparency, and a faded control fails the accessibility floor and vanishes in screenshots. |
| Predictability §9 | `button:active`'s `translate(1px, 1px)` is the entire motion budget, and remains the only transform this theme adds. |

## NOT applied, and why

### 1. `transition: none` / `animation: none` (iron law 2)
**Kept at `0.001s` with a height-only property list.** This is not an oversight —
it is [[ADR-001]] and three shipped versions of live evidence. `transition: none`
never fires `transitionend`, and spoiler/accordion/modal JS commonly waits for
that event to set `height: auto` and release a scroll lock; forcing `none` left
forum spoilers stuck mid-open with broken page scroll (aechat.ru). Forcing the
property list wider than `height/max-height/min-height` broke Ant Design dropdown
hit-testing (chat.qwen.ai, isolated by live binary search). 0.001s reads as
instant to a human while keeping the event pipeline alive.

UI.md's law assumes the author owns the JavaScript. Here the site owns it, and
zeroing motion outright breaks state machines we do not control. **The visual
intent of the law is met; the literal value is not, deliberately.**

### 2. Global `margin: 0` (UI.md base CSS)
**Not applied.** In a hand-built screen the author replaces those margins with
deliberate spacing. Applied to arbitrary sites it collapses every paragraph, list
and heading gap into one unreadable wall — which fails UI.md's *own* "text must
never feel jammed" (core principle 4) and "screenshot legibility" (principle 7).
Following one line of the spec to break two of its principles is not conformance.

### 3. Global `box-sizing: border-box` (UI.md base CSS)
**Not applied**, and this one was already tried and reverted in this project for
breaking flex layouts. It stays forced on buttons/inputs/table cells, where it
protects our own forced borders from shifting a site's measurements.

### 4. `body { overflow-x: hidden }` (UI.md base CSS)
**Not applied.** On a hand-built screen this enforces "fits 640x480". On someone
else's site it silently *hides real content* that has scrolled out of view. UI.md
law 4 is a design instruction, not a clamp to apply to pages you did not lay out.

### 5. Status colours by class name
**Not applied as CSS.** `[class*="error" i]` matches `error-boundary`,
`[class*="valid" i]` matches `validation-container` — both large wrappers, and
painting one solid red or green is exactly the "might help some other site"
over-reach that already broke two real sites in this file's history. Semantic
snapping happens in JS instead, gated on the site having **already painted** a
saturated green/amber/red background: evidence, not a name. Same reasoning
retired the class-name-based 10px "metadata" targets.

### 6. `--success`/`--warning`/`--danger` as TEXT colour
**Not applied.** They are background tokens: on `--backgroundSoft` they measure
2.6:1 / 3.4:1 / 1.8:1, far under the WCAG AA 4.5:1 UI.md also demands. Saturated
text snaps to `--textPrimary` instead. UI.md settles this tie itself — "error text
must be readable without color alone."

### 7. `--accentTeal` for links
**Not applied.** `#008080` on `#1A0F05` is 3.7:1, under AA. The retired `#9DD9F9`
was worse in a different way — it traced to no token at all, an iron-law-5
violation on the most common coloured element on the web. Links use
`--borderHighlight` (7.8:1), visited `--textSecondary` (6.2:1); `--textMuted` was
rejected at 3.3:1.

## Traps for future work

- **The base type-ladder selector out-specifies every exception.** Its six
  `:not([class*="…" i])` attribute matches score it (0,6,4); a plain
  `h1 { font-size: 16px }` is (0,0,1) and loses even with `!important` on both.
  The first cut of this rule silently flattened every heading to 12px because of
  it. The exceptions are therefore carved OUT of the base selector (disjoint
  selectors, no specificity race). The `font-weight` pair had the identical bug
  and is fixed the cheaper way — a `:root` / `:host` prefix, since no attribute
  matches are involved there.
- **`node --check` cannot see inside the CSS template literals.** To JavaScript
  they are just strings. A paragraph pasted after a comment's closing `*/` left
  loose prose and a stray `*/` in the middle of `GLOBAL_CSS`; `--check` passed,
  the file loaded, and the browser's CSS parser silently discarded rules while
  recovering — the whole type ladder stopped applying with no error anywhere. It
  was caught only by measuring computed font sizes on a live page.
  `tools/check-css.js` now fails on stray/unclosed/nested comments, unbalanced
  braces and off-palette colours; `release.ps1` gates on it. The guard was
  validated by injecting all three fault classes and confirming each is caught.
- **Every new universal rule raises the cost of every recalc, everywhere.**
  v1.4.0's added universals took the settled idle cost from 0.09 % to 0.14 % and
  roughly 6x'd the per-force-pass time. [[ADR-002]]'s batching means that cost is
  paid once per sweep instead of per element, which HIDES it — do not read the
  good numbers as headroom for more `*`-with-`:not()` rules.
- **Forced `height: 20px` on single-line inputs is deliberate and has a known
  cost**: absolutely-positioned adornment icons inside a site's own search widget
  can end up vertically off-centre. Accepted trade — a site's 48px pill search bar
  is one of the most recognisable pieces of its identity, so exempting it would
  defeat the goal.
