[P1] [W2-001] desktop/modules/targets.ps1 / Invoke-Obsidian multi-vault apply/revert transaction

EVIDENCE:
- Invoke-Obsidian captures an operation-wide `$preStates` array before processing vaults:
  - Revert: approximately lines 2159+
  - Apply: approximately lines 2211+
- Each vault is then mutated sequentially.
- On a vault-specific failure, the catch restores only `$preThis`, the currently failing vault:
  - Revert: `try { Restore-VaultPreState $preThis } catch { }`
  - Apply: `try { Restore-VaultPreState $preThis } catch { }`
- Earlier successfully mutated vaults are not restored in either failure path.
- Both paths collect `$failedVaults` and throw before reaching the later Invoke-TargetCommit call when any vault failed.
- Therefore the operation-wide rollback callback associated with `$preStates` never executes for this failure class.
- Apply can consequently leave vault 1 successfully themed while vault 2 is restored/failed and the manifest is never advanced.
- Revert can leave vault 1 already reverted, including consumed recovery state, while vault 2 fails and the manifest remains installed.
- The Apply catch comment claims the failing-vault restore prevents "vault 1 themed without a manifest", but the implementation restores vault 2 only; the comment and actual transaction scope contradict one another.

- tools/test-ownership.ps1 contains two-vault failure coverage, but its assertions check process failure and manifest state only. It does not assert that vault 1 returns byte-for-byte to its pre-operation state after vault 2 fails.

The user-visible multi-vault operation is treated as one transaction by its manifest, but its rollback boundary is only one vault wide. A late vault failure can therefore leave already-processed vaults in the new state while the manifest remains in the old state. Revert has the inverse split-brain and may additionally consume successful earlier-vault recovery artifacts. Rollback failure for the currently failing vault is silently discarded.

- Capture every vault pre-state before the first mutation.
- If any vault fails, restore every vault that may have been touched, including previously successful vaults and the failing vault.
- Aggregate rollback errors rather than swallowing them.
- Do not consume per-vault authoritative recovery artifacts until the whole operation has crossed its commit boundary, or make consumption independently reversible until manifest commit completes.
