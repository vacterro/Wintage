EVIDENCE:
- `tools/install-electron.js:404-428` handles `themed-relocated` Revert by:
  1. reading `app/app.asar` into `pre.movedAsar`;
  2. renaming `app/app.asar -> app.asar`;
  3. optionally renaming `app/app.asar.unpacked -> app.asar.unpacked`;
  4. deleting the entire `app/` directory at line 416.
- On any failure after that deletion, rollback lines 421-423 try to write `pre.movedAsar` back to `app/app.asar` BEFORE recreating `app/`. The parent directory no longer exists, the write failure is swallowed, and line 423 then deletes the live root `app.asar`.
- `captureAppDir()` at `tools/install-electron.js:584-590` captures only `package.json`, `shim.cjs`, `wintage.css`, and `wintage-status.txt`; it does not capture `app.asar` or `app.asar.unpacked`.

  - immediately before failing Revert: root `app.asar` absent, moved `app/app.asar` present;
  - Revert with `WINTAGE_TEST_FAIL_AFTER_REVERT=1` exited nonzero and printed the exact-restoration claim;
  - afterwards BOTH root `app.asar` and moved `app/app.asar` were absent: no live path retained the archive bytes.
- The advertised parent safety net does not cover this path. `desktop/install.ps1:727` calls `Save-ElectronStateSnapshot` before Revert, but `desktop/modules/targets.ps1:201-227` classifies every `themed-relocated` state as `repaintOnly` and therefore snapshots only small `appfiles`, not `app/app.asar` or its unpacked companion. `Restore-ElectronStateSnapshot` consequently cannot recover the archive destroyed by the child rollback.
- `tools/test-electron-state.js:310-329` exercises `WINTAGE_TEST_FAIL_AFTER_REVERT` only in `--in-place` mode. Relocation Revert has no equivalent failure-transaction regression.

DEFECT:
A simulated or real failure after the destructive relocation-Revert swap can destroy the application's only `app.asar`, leave `app.asar.unpacked` in a structurally inconsistent location, and still emit a false "exact pre-operation state" recovery message. The parent installer snapshot also omits the moved archive precisely because it infers "repaint-only" from themed state without considering that the requested operation is Revert. This is a verified application-breaking/data-loss transaction failure.

- Make relocation Revert a checked reverse transaction, symmetrical with the already-strong relocation Apply transaction.
- Never delete the root archive until the moved archive has been successfully recreated at `app/app.asar`, or recreate `app/` before attempting that restore.
- Snapshot/restore `movedAsar` AND `movedUnpacked` as first-class state, including presence and byte/directory content.
- Collect and inspect every rollback failure. Do not swallow archive/unpacked restore errors and never print "exact" unless post-rollback structural and byte checks pass.
- Change `Save-ElectronStateSnapshot` to accept operation intent or mutation class. A Revert of a themed Electron target must use a full structural snapshot; only a genuine palette repaint may use the lightweight snapshot.
- Preserve every surviving recovery location when rollback is incomplete, matching the discipline already used by relocation Apply.

VERIFY:
