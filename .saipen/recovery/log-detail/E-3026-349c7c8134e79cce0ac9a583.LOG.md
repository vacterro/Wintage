When INTAKE_BUDGET expired on the very record that completed a frame, the loop exited with that frame still in pendingIntake; hasIntakeWork() then reported no work, so no continuation was scheduled and the frame was never revisited -- it held its whole records array, and every DOM node those MutationRecords reference, for the rest of the document's life, while still consuming one of the eight MAX_PENDING_BATCHES slots. Fix: releaseSpentFrames() runs on every drain exit before hasIntakeWork() is consulted; retainedRecords/maxRetainedRecords count retained input in records instead of batches, which is the unit actually retained. The finding's proposed TOTAL_PENDING_RECORDS reject-to-overflow cap is deliberately NOT adopted: Fixture C's 100,000 attribute targets are DETACHED elements, so a whole-document continuation cannot cover them and the cap would silently drop 100,000 repairs that the current incremental drain guarantees.
