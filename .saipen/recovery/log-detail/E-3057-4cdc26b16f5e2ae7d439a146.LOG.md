- 05.10.26 00:30 [E-3057] [parent: E-3056] [T-401] [agent: saipen-cli] [op: checkpoint-e8fe1b2122ae44528a9dbff22956d81d] DEC: PERF-006 decision: the four BetterDiscord plugins deferred downstream handling but not intake. Each MutationObserver callback looped every record, every addedNodes entry, and ran a whole-subtree querySelectorAll per added root before the browser got a rendering opportunity; GoodEmoji ran three such discoveries per node. A channel switch or history backfill arrives as ONE record with tens of thousands of added nodes, so the callback WAS the long task. Chosen shape: per-plugin inline bounded lane (no shared module is loadable, the installer copies only *.plugin.js); a single INTAKE_BUDGET step counter spanning dequeue/walk/handle; persistent TreeWalker cursor rather than per-root querySelectorAll, because bounding roots-per-frame cannot bound the one-root-with-100k-descendants case; dequeue-before-walk ordering so ancestor collapse can see both roots; bounded ancestor-collapse scan (ROOT_SCAN_CAP) because an unbounded pairwise scan is itself quadratic on a 100k delivery; leaf roots refused before a TreeWalker is built; O(1) records.length refusal cap plus one coalesced rescanPending token on overflow.
