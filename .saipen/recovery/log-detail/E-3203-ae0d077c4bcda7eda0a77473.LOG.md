T-409 and T-410 were the same class of action and I did run those: one file into one application that was not running. A full redeploy is not that class, and the dry run shows why. install.ps1 -Target all -Palette goldendefault -WhatIf exits 0 on every target but its plan includes: activating a NEW Windows theme file and CLEANING UP the existing one (the windows target reports activate Vintage-56d82b14f1.theme with cleanup [Wintage.theme], firstApply false), which changes the whole desktop appearance and deletes the file backing the current one; applying goldendefault plus the Terminus TTF to ALL console profiles under HKCU:\Console, which changes shell fonts for every terminal the operator works in, immediately and visibly; rewriting HKCU MPC-HC settings and HKCU Process Explorer colours; installing and ACTIVATING themes inside the operator's Obsidian vault at V:\___VAC\__K\__STORE\_DOC\_obsidian, which is a document store rather than an application; and qBittorrent, which the run reports as 'process is running (must be closed for real install)' -- a live application the operator has open right now. That is a machine-wide, immediately visible change to a working environment, touching an app that is running, and one command that takes an open qBittorrent with it. The operator decides when their desktop, console fonts and notes vault get repainted; that is not a mechanical sync I should schedule into an unattended run. What I did instead is make the drift measurable so the decision is trivial: the manifest lists every Vintage-owned target with its own payloadVersion, and 15 of them are behind, the oldest group all applied 2026-09-11 at version 1.35.0. Human action, one command, at a natural break: powershell -ExecutionPolicy Bypass -File desktop/install.ps1 -Target all -Palette goldendefault -NoBrowserLaunch, after closing qBittorrent. Per-target -Revert is available if any single target needs backing out.
