Root cause: pruneShadowRegistry was one synchronous task over the whole piercedRoots registry, and because MutationObserver has no per-target unobserve, a single detached root made it disconnect the shared shadowObserver and re-observe EVERY survivor; measured 50,000 roots + one dead root = 50,000 connectivity checks + 49,999 observe() calls in one invocation, none of it charged to addWorkPressure. Repair: a resumable SCAN/STAGE/SWAP state machine. SCAN walks a persistent Set iterator and finds detached roots across many tasks. STAGE fills a REPLACEMENT observer incrementally while the outgoing one stays live, so no root is ever unobserved and the dead-root removal no longer costs a registry-wide rebuild in one task. SWAP takes the outgoing records, repoints shadowObserver (now let, not const, so pierceShadow reaches the current generation), disconnects the outgoing observer, then clears the migration flag. Exactly-once across the overlap is a superset argument: the outgoing observer has had every survivor registered since before the first root was staged, so anything the staged observer sees while shadowMigrationActive is already in the outgoing queue and is dropped; the swap order takeRecords -> repoint -> disconnect -> flag hands each record to exactly one of the two. shadowPruneQueued is held for the whole cycle so a burst of removal batches cannot stack concurrent scans, every task charges addWorkPressure, and suspendRepainter now disconnects and nulls a staged observer left over from a mid-migration teardown. Explicit shadowPrunePhase was required: with a single nullable cursor, every STAGE task re-armed a fresh SCAN and the cycle never advanced -- that was caught by the 50,000-root gate, not by inspection.
