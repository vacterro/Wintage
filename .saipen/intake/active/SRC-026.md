# User request

priority: P1
verify: the requested change is present and demonstrated against the user own description of it

## Request

Wintage

MISSION

Add a complete TERMINAL FONTS subsystem to Wintage.

The user wants to visually browse monospace fonts in real time and choose which
font Wintage applies to:

- Windows Terminal
- classic Console Host
- cmd.exe
- Windows PowerShell
- other HKCU\Console-backed console profiles where the selected face is genuinely supported

This is a NEW FEATURE lane.

Do NOT reopen audit/7.
Do NOT attach this feature to old T-262/T-280 work.
Do NOT disturb the completed Process Explorer implementation.

Create a new canonical SAIPEN user-request ticket/receipt and execute this feature
as a bounded multi-milestone implementation.

Do not ask `continue?` between normal milestones.

CURRENT ARCHITECTURE

The current tree already has:

- a Windows Terminal target
- a conhost target
- terminal health checking
- transactional Apply/Revert
- exact owned-field restoration
- GUI pseudo-tabs:
  - THEMES
  - BETTERDISCORD
- palette-aware GUI styling
- `$CONSOLE_FONT = 'Terminus (TTF) for Windows'`

Current documentation states:

- Windows Terminal uses Terminus (TTF) for Windows
- conhost currently applies Consolas because proportional fonts are unsafe
- terminal health validates the configured font face

The new feature must generalize this cleanly instead of layering special cases
around the current hard-coded Terminus/Consolas behavior.

USER INTENT

The user currently likes Terminus but wants to compare it visually against other
popular monospace fonts.

They want:

1. a dedicated GUI tab for terminal fonts;
2. approximately 20 popular monospace fonts available in Wintage;
3. immediate live preview while moving through the font list;
4. convenient installation of a selected bundled font;
5. ability to select which font Wintage applies to Windows Terminal;
6. ability to use the selected font for cmd / PowerShell / Console Host when the
   actual Windows console host supports that face;
7. safe fallback when a font is previewable but cannot be used by classic conhost.

- selected font changes
- size changes

System.Drawing.Text.PrivateFontCollection or another safe process-local mechanism.

The preview must not register the font system-wide merely because the user clicked
it in the list.

LICENSE RULE

Do not download or redistribute a font until its redistribution license is
positively verified.

Accept suitable open-source/free redistribution licenses such as:

- SIL Open Font License
- Apache-2.0 where applicable
- Ubuntu Font Licence
- MIT / compatible font-specific licenses
- other licenses only after confirming redistribution permission

Do not assume that "free download" means redistributable.

For every bundled family:

- retain the required upstream license text;
- retain attribution if required;
- record source/version;
- record SHA-256.

If any family above cannot be legally/cleanly vendored, replace it with another
well-known open-source monospace family and record the substitution.

DOWNLOAD / VENDOR PIPELINE

Add a deterministic maintainer tool, for example:

tools/sync-terminal-fonts.ps1

It must:

1. read a pinned source manifest;
2. download only from official project repositories/releases or another
   authoritative upstream distribution;
3. validate expected SHA-256;
4. validate expected filenames;
5. place files into deterministic repo locations;
6. keep required license files;
7. never execute downloaded content;
8. refuse hash mismatch;
9. support a verify-only/offline mode;
10. produce deterministic catalog state.

Do NOT download "latest" blindly at Wintage runtime.

Pin every font to an explicit version/revision or immutable artifact.

Runtime Wintage must work offline with the vendored files already present.

REPO SIZE DISCIPLINE

Do not vendor entire font families containing twenty weights and every format.

For this feature, one normal monospace face per family is enough for the baseline
preview/apply workflow.

Prefer:

- Regular static TTF

or, if upstream only reasonably ships it:

- one appropriate variable TTF

Do not vendor:
- webfonts
- WOFF/WOFF2 duplicates
- every bold/italic weight
- source build trees

unless a specific family requires them.

INSTALLATION SAFETY

IMPORTANT:

The current code deliberately avoids silently installing/removing fonts because
font registration has previously produced machine-wide side effects.

Preserve that safety principle.

Browsing a font MUST NOT install it.

Theme Apply MUST NOT silently install twenty fonts.

Font installation must be an explicit operator action from the TERMINAL FONTS tab:

INSTALL SELECTED

Prefer per-user installation when Windows supports it safely.

Before implementing automated installation, prove the correct Windows 10
per-user registration semantics.

Do not manipulate shared/system font registration casually.

Do not uninstall fonts that Wintage did not install.

If safe automated per-user install cannot be proven, use the Windows-owned
installation UI/Shell verb for the selected local font and then re-probe.

The UX may require one explicit confirmation from Windows.
That is acceptable.

Wintage must never lie and report INSTALLED until a new process-visible font probe
resolves the requested family.

FONT INSTALL OWNERSHIP

If Wintage itself implements a safe per-user font installation path:

- persist exact ownership metadata;
- distinguish pre-existing from Wintage-installed fonts;
- never overwrite an unrelated existing font family;
- verify family/style identity from the actual file before registration;
- install atomically where practical;
- do not automatically uninstall on ordinary terminal Revert.

Font installation and terminal preference are different lifecycles.

Reverting a terminal theme should restore terminal settings.
It should not unexpectedly remove a font from the machine.

If an explicit UNINSTALL FONT operation is added, allow it only for fonts whose
installation is proven to be Wintage-owned.

CONSOLE HOST / CMD / POWERSHELL

Treat classic Console Host separately from Windows Terminal.

Do NOT assume that every TTF which previews correctly can be used by conhost.

For every candidate selected for conhost:

1. verify it is monospace/fixed-pitch sufficiently for console use;
2. verify Windows can actually resolve the family;
3. verify the classic console host accepts the face or the required registration
   already exists;
4. refuse safely if not supported.

Do not silently fall back to another font while reporting success.

If a selected font is valid for Windows Terminal but invalid for conhost:

UI must show something like:

Windows Terminal: READY
Console Host: UNSUPPORTED

and allow Apply to Windows Terminal only.

CMD / WINDOWS POWERSHELL SEMANTICS

Remember:

cmd.exe and Windows PowerShell do not own their fonts themselves when hosted by
classic conhost.

The target is HKCU\Console / relevant console profiles.

Do not invent separate cmd and powershell font installations when the same Console
Host settings surface is authoritative.

If profile-specific HKCU\Console overrides exist, follow the existing conhost
ownership model.

CONHOST FALLBACK SAFETY

Never substitute a proportional font into a fixed cell console.

If the selected font is unsupported:

- refuse conhost apply;
- preserve existing conhost state;
- explain the reason.

Do not claim success because Windows silently substituted another face.
