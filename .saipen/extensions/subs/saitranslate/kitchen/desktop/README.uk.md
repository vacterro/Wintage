# Wintage для десктопних застосунків

Юзерскрипт тематизує веб. Це тематизує програми навколо нього, з тих самих палітр, щоб браузер і застосунки перестали сперечатися про те, що означає темне золото.

За кожним рішенням тут стоїть одне правило: **застосунки оновлюються самі, і оновлення не повинно тихо нічого ламати.** Де ціль має місце у вашому власному профілі, тема йде туди і переживає оновлення. Де ні — інсталятор розрахований на повторний запуск — і так і каже, замість того щоб удавати, що все персистентно.

## GUI

Двічі клацніть **`Wintage Installer.vbs`** у корені репозиторію, щоб відкрити його без консольного вікна, або запустіть це напряму для діагностики:

```powershell
powershell -File desktop\WintageInstaller.ps1
```

Список тем із кольоровими зразками, цілі, знайдені на цій машині, живий Win95-прев'ю та всі двадцять один кольоровий токен як редаговані свотчі. Редагування будь-якого свотча розгалужує палітру в **Custom**, а не змінює випущену тему під вами. Панель праворуч показує живий WCAG-контраст для трьох токенів, що несуть текст — палітру, яка там FAILить, build-гейт однаково відхилить, тож краще побачити це до Apply, ніж після.

Цілі поділені на два списки, доступні з клавіатури: **MY APPS** містить портативні/з вихідного коду інструменти CodeNomad, SAIPENVIEW, SmartVac і WildRift; **POPULAR APPS** містить Windows, OBS, термінали, редактори та інше встановлене програмне забезпечення. ALL/NONE та Apply/Revert діють на обидва списки, не змінюючи їх групування.

Вікно одягає палітру, яку збирається встановити. Це найшвидший доступний прев'ю, і це тримає інструмент чесним: палітра, яка робить це вікно нечитабельним, видимо нечитабельна.

Apply викликає `install.ps1`. Є рівно один шлях коду, який встановлює тему, тож GUI не може відхилитися від командного рядка.

## Командний рядок

```powershell
.\desktop\install.ps1                                  # що тут є, що тематизовано, з якою палітрою
.\desktop\install.ps1 -Target freebuff -Palette klite  # один застосунок, одна палітра
.\desktop\install.ps1 -Target all -Palette goldendefault # все
.\desktop\install.ps1 -Target all -WhatIf              # сказати, що зміниться, нічого не чіпати
.\desktop\install.ps1 -Target freebuff -Revert         # скасувати одне
```

`-Palette` за замовчуванням `goldendefault` (**Golden Default**). GUI відкривається на тій самій палітрі та перевіряє кожну доступну ціль. Перемальовування вже тематизованого застосунку працює, поки він працює; перше встановлення — ні, бо архів використовується.

### Видалення реклами FreeBuff

FreeBuff (десктопний застосунок AI-асистента) має власну рекламну мережу: renderer-бандл (`resources/orchestrator/ui/assets/index-*.js`) рендерить картку `sponsored-ad` і банер у треді, а оркестратор (`resources/orchestrator/orchestrator.js`) надає маршрути `/api/ad/slot|impression|click`, що викликають віддалений рекламний аукціон. Shim лише тематизує застосунок; він не чіпає ці файли.

`desktop/patch-freebuff-ads.js` вирізає рекламу на рівні байтів:

- renderer: місця викликів рекламної картки/банера стають `null`, а методи клієнта API `adSlot` / `adImpression` / `adClick` стають no-op — нічого не рендериться і жоден запит `/api/ad/*` не покидає renderer;
- оркестратор: усі три маршрути `/api/ad/*` перестають викликати рекламну мережу, а inline-запит реклами живого ходу (`maybeRequestAd`) коротко замикається.

Ім'я бандла містить hash збірки, тому патч виявляє поточний бандл із `index.html` замість постачання прив'язаного до версії пейлоаду — саме це дозволяє йому переживати оновлення. Оригінали резервуються в `_orig-backup-<timestamp>/` у теці встановлення; `--revert` відновлює найновіший.

**Майбутні версії обробляються на двох незалежних рівнях:**

1. **Байтовий патч із regex-фолбеками.** Кожна ціль має точний рядок для поточної збірки *і* fallback на регулярному виразі, прив'язаний до того, що мініфікатор не може перейменувати — літералів шляху `/api/ad/*`, протокольного дискримінатора `case"ad":`, класу `sponsored-ad` і розміщень `variant:"banner"` / `variant:"card"`. Оркестратор не мініфікований (читабельні імена на кшталт `maybeRequestAd` і `app.ads.slotAd`), тому його точні рядки тримаються довго; renderer-бандл мініфікований, тому його regex-фолбеки беруть верх, щойно наступна збірка перейменує його ідентифікатори.
2. **Блокування на рівні shim (`targets/electron/shim.cjs`).** Незалежно від бандла повністю: будь-який fetch/XHR до URL `/api/ad/` відхиляється всередині сторінки, а будь-який елемент, чий клас містить `sponsored-ad`, ховається, щойно з'являється. Навіть абсолютно нова збірка, якої цей скрипт ще не знає, не може показати рекламу.

```powershell
node .\desktop\patch-freebuff-ads.js           # патч (спершу резервує)
node .\desktop\patch-freebuff-ads.js --sound "C:\...\my.mp3"   # патч + кастомний звук завершення (wav/mp3/ogg/flac/m4a/aac)
node .\desktop\patch-freebuff-ads.js --scan    # які рекламні маркери несе ЦЯ збірка?
node .\desktop\patch-freebuff-ads.js --verify
node .\desktop\patch-freebuff-ads.js --revert
```

Він запускається автоматично як частина `install.ps1 -Target freebuff` і його потрібно перезапускати після кожного оновлення FreeBuff (оновлення відновлюють стокові файли). Якщо збірка змінить форму, скрипт назве ціль, яка більше не збігається — запустіть `--scan`, щоб побачити, що несе нова збірка, і оновіть рядки там.

**Звук завершення FreeBuff.** Renderer грає `chime-<hash>.mp3`, коли хід завершується. Патч знаходить його так само, як і бандл (ім'я містить hash збірки), тож `--sound <file>` встановлює ваш власний звук (wav/mp3/ogg/flac/m4a/aac) поверх нього і тримає стоковий файл як `chime-*.mp3.bak`; `--revert` відновлює його. `--verify` повідомляє, який із них активний.

### Кнопка звуку FreeBuff (GUI)

`WintageInstaller.ps1` має маленьку кнопку **FB SOUND** під стеком APPLY / REVERT. Вона лише зберігає *вподобання*; `install.ps1 -Target freebuff` читає той самий файл і передає його патчу як `--sound`, тож реклама і звук застосовуються за один запуск:

- **Лівий клік** — виберіть аудіофайл (OpenFileDialog, wav/mp3/ogg/flac/m4a/aac) і почуйте його відтворення одразу: PCM WAV через System.Media.SoundPlayer, кожен інший формат через WPF MediaPlayer (Media Foundation, async, тож вікно ніколи не завмирає). Вибір запам'ятовується у `%APPDATA%\Wintage\freebuff-sound.txt` (на машину, поза git-чекаутом, точно як запам'ятовані теки вихідного коду).
- **Правий клік** — очистити вподобання назад до стокового chime FreeBuff (також зупиняє будь-який прев'ю, що ще грає).
- **COPY** — копіює вибраний звук у саме репо (`sounds\freebuff.<ext>`, зберігаючи розширення джерела) і перенаправляє вподобання на цю копію, тож звук переживає видалення чи переміщення оригінального файлу. Увімкнено лише поки встановлено кастомний звук; повторне копіювання просто перезаписує копію в репо. Тека `sounds/` — звичайний git-відстежуваний контент, тож коміт дозволяє звуку переживати й повторні клони.

Прев'юються лише розпізнані аудіоконтейнери — заголовок спершу зондується, тож вибір не-аудіо оголошується, а не тихо грає нічого.

Кнопка показує `ON`, поки встановлено кастомний звук; наведення на неї показує шлях. Застосуйте ціль `freebuff` після цього (відмітьте FreeBuff + APPLY або запустіть `install.ps1 -Target freebuff` з терміналу), щоб воно набуло чинності.

### Термінали

`terminal` пише кольорову схему `Wintage` у кожен виявлений стабільний, Preview або неупакований файл налаштувань Windows Terminal і обирає її через `profiles.defaults`, разом із консольно-безпечним Consolas 12 і aliased текстом. Оригінальний файл зберігається байт-у-байт поруч, а `-Revert` відновлює його.

`conhost` покриває класичний `cmd.exe`, Windows PowerShell, консольні профілі Git CMD/Bash та інші існуючі дочірні елементи `HKCU\Console`. Він пише повну 16-кольорову таблицю палітри і в кореневі дефолти, і в кожне існуюче перевизначення, потім відновлює лише значення, які торкався. Consolas застосовується і там, бо пропорційна Verdana стикається всередині фіксованої сітки клітинок, яку використовують обидва термінальні хости.

### Браузери та Tampermonkey

`browsers` знаходить профілі Chrome, Edge, Brave, Cent, Vivaldi та Opera зі встановлених розташувань і з портативного кореня, на який ви вкажете (`-PortableRoot`, або запам'ятований запис `portable` у `paths.json`). Його статус показує і кількість профілів, і скільки містять Tampermonkey. Apply копіює вибрану chrome-тему в стабільну теку `%LOCALAPPDATA%\Wintage\browser-theme`, кладе цей шлях у буфер обміну та відкриває кожен точний профіль на `chrome://extensions` плюс сторінку Install/Update юзерскрипта Wintage. Профілі без Tampermonkey також отримують його сторінку в Chrome Web Store.

Chromium навмисно забороняє тихе встановлення розширень поза магазином на некерованій Windows-машині. Тож перше встановлення браузерної теми потребує одного підтвердження **Developer mode → Load unpacked** на профіль. Оберіть скопійований шлях; після цього Wintage продовжує замінювати ту саму стабільну теку, коли палітри змінюються. Підтвердьте також **Install/Update** у Tampermonkey. Жоден браузерний `Preferences`, Secure Preferences або файл LevelDB Tampermonkey не редагується за спиною браузера. Якщо Tampermonkey не було присутнім, встановіть його з відкритої вкладки магазину та оновіть уже відкриту вкладку `wintage.user.js`, щоб отримати екран Install.

### Windows

`windows` встановлює й одразу активує контент-адресований `%LOCALAPPDATA%\Microsoft\Windows\Themes\Wintage-<hash>.theme`. Він починає з активної теми та замінює лише задокументовані секції кольорів, курсорів і візуального стилю. Шпалери, звуки та іконки робочого столу лишаються незмінними; курсори навмисно перемикаються на встановлену схему `___CURRENT___`. Перша активна тема зберігається байт-у-байт як `Wintage.original.theme`; зміни палітри зберігають цю базову лінію, а `-Revert` знову її активує. Сучасні елементи керування Windows досі походять із підписаного візуального стилю Aero — Wintage змінює його підтримувані входи темного режиму, акценту та класичних системних кольорів, а не замінює захищені файли `.msstyles`. Активні та неактивні заголовки ділять приглушений піднятий колір поверхні палітри; яскраве підсвічування залишається зарезервованим для країв тексту/виділення. Попередній неактивний акцент заголовка знімається окремо та точно відновлюється `-Revert`. Контентний hash дає Windows нову ціль асоціації файлів, коли та сама палітра перебудовується, тож повторне застосування оновленої палітри не плутається з no-op; застарілий файл Wintage видаляється після того, як Windows підтвердить новий активним.

### OBS Studio

`obs` генерує варіант OBS 30.2+ поверх підтримуваної бази Yami Classic, встановлює його в `%APPDATA%\obs-studio\themes` і пише його стабільний ID теми в `user.ini`, тож вибрана палітра Wintage уже вибрана при наступному запуску. Закрийте OBS перед Apply або Revert: OBS переписує `user.ini` при виході. Перше застосування резервує і попередній вибір, і будь-яку тему з тим самим ім'ям байт-у-байт.

### Electron застосунки

`resources/app.asar` переміщується в `resources/app/app.asar` (його сусід `app.asar.unpacked` рухається разом із ним — це поєднання за ім'ям файлу, і розділення ламає кожен нативний модуль), а маленький `shim.cjs` займає звільнений слот `resources/app`. Shim впорскує стильовий лист і потім завантажує оригінальний архів. **Жоден байт застосунку не переписується**, лише переміщується; `-Revert` переміщує його прямо назад.

Стильовий лист не пишеться для цих застосунків — він витягується з `wintage.user.js`, тож кожне виправлення бевелів, скролбарів і типової драбини, зроблене для браузера, потрапляє і сюди, без другої копії, що гниє.

Дві нотатки, які варто знати заздалегідь:

- Очевидний підхід — покласти `resources/app` поруч з архівом і сподіватися, що Electron віддасть йому перевагу — **не працює і тихо провалюється**. Electron спершу шукає `app.asar`. Застосунок запускається чудово, а тема ніколи не запускається.
- Shim — це `.cjs`, не `.js`, навмисно. Його `package.json` копіюється з власного `package.json` застосунку, тож застосунок зберігає своє ім'я та версію (ім'я вирішує, де живе userData — shim, який перейменує його, переміщує застосунок у порожній профіль). Якщо цей маніфест каже `"type": "module"`, `.js` shim помирає на своєму першому `require`.

### Десктопний застосунок Claude: на місці, і фрейм, у якому він реально малює

Claude не може використати переміщення вище, бо `OnlyLoadAppFromAsar` увімкнено на рівні fuse — Electron завантажує `resources/app.asar` і нічого іншого, тож shim у `resources/app` ніколи не запуститься. Він патчиться **на місці** натомість: архів резервується, його `main` у `package.json` переписується на `"../wintage-shim.cjs"` (доповнюється до тієї ж довжини байтів, щоб кожен зсув в архіві лишався валідним), а hash цілісності кожного файлу оновлюється відповідно. `-Revert` відновлює резервну копію.

Інсталятор досі читає fuse **перед тим, як щось переміщує**, і відмовляється з причиною, коли вони блокують — `EnableEmbeddedAsarIntegrityValidation` зробив би перепис вище провалом при запуску, а не при встановленні. Перевірте будь-який застосунок самі:

```powershell
node ..\tools\electron-fuses.js "<шлях до exe застосунку>"
```

Друга половина була значно тихішою проблемою. `BrowserWindow` Claude рендерить тонку оболонку, а **весь видимий застосунок — це `WebContentsView`**, приєднаний до неї. Shim раніше хукав `browser-window-created`, тож впорскував стильовий лист в оболонку, повідомляв про успіх у `wintage-status.txt` і не змінював нічого видимого. Тепер він хукає `web-contents-created`, який покриває вміст вікна, `WebContentsView`, `BrowserView`, `<webview>` гості та попапи однаково.

### Obsidian

Спільнотна тема пишеться в `.obsidian/themes/` кожного сховища — всі шістнадцять палітр одразу, точно як ціль VS Code, тож ви перемикаєтеся між ними в **Settings → Appearance** без повторного запуску. Шаблон походить із рукотворної теми `VintageWin95`, яка вже була у сховищі, кожен колір замінений токеном, якому він дорівнював. `-Palette <slug>` задає, яка активна при встановленні; `appearance.json` спершу резервується, а `-Revert` видаляє лише теми `Wintage *` і відновлює ваш попередній вибір — рукотворна тема в тому самому сховищі ніколи не чіпається.

### SAIPENVIEW

Його фронтенд уже оголошує імена токенів Wintage у власному `:root`, тож цей патч переписує **лише значення токенів** — ніколи селектор, шрифт, ширину бордера чи падінг. Нічого, що впливає на box model, не змінюється, тож текст не може зсунутися. Це навмисно: попередній підхід додавав весь браузерний стильовий лист зверху, а `wintage.css` написаний для довільних веб-сторінок — універсальні селектори, що змушують шрифт, драбину розмірів, 2px бордери та висоти елементів керування. На застосунку, який уже має власний лейаут, це рухає все.

Перевірено маскуванням кожного hex і дифом проти резервної копії: структурно ідентично, відрізняються лише літерали кольорів. `--link` повідомляється як не оголошений там (його markdown-посилання читають `--accentTeal`, який цей патч задає), а не впорскується — додавання змінної, яку застосунок ніколи не читає, було б мертвим вантажем.

### MPC-HC (K-Lite)

Нативний Win32, без стильового листа і без точки впорскування, а кольори його темної теми скомпільовані в програму — жодне значення реєстру їх не показує. Тож ця ціль **не може нести палітру**. Що вона робить: вмикає темну тему та застосовує правила типографіки UI.md до OSD, який є тією єдиною поверхнею, яку MPC-HC дозволяє користувачеві контролювати. Попередні налаштування експортуються в `desktop/backup/mpc-hc-settings.reg` спершу.

Закрийте MPC-HC перед застосуванням: він переписує свої налаштування при виході.

## Перебудова

Усе під `desktop/out/` генерується з `themes/*.json`. Воно не відстежується в git (T-160), тож свіжий клон має зібрати його один раз перед встановленням:

```powershell
node ..\tools\build-desktop.js          # перебудувати всі цілі
node ..\tools\build-desktop.js --check  # вийти 1, якщо щось застаріло
```

`release.ps1` запускає збірку та кожен гейт, тож реліз не може відправити вихід, який відхилився від палітр.
