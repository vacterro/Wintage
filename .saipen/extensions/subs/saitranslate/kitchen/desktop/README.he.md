# Wintage עבור אפליקציות שולחן עבודה

סקריפט המשתמש נותן נושא לאינטרנט. זה נותן נושא לתוכנות שמסביבו, מאותן פלטות, כך שהדפדפן והאפליקציות מפסיקים לחלוק על המשמעות של זהוב כהה.

יש כלל אחד מאחורי כל החלטה כאן: **אפליקציות מעדכנות את עצמן, ועדכון אסור לשבור משהו בשקט.** במקום שבו ליעד יש מקום בפרופיל שלך, הנושא גר שם ושורד עדכונים. במקום שבו אין, המתקין כתוב כך שירוץ שוב — ואומר זאת, במקום להעמיד פנים שהוא נשמר.

## ה-GUI

לחצו פעמיים על **`Wintage Installer.vbs`** בשורש הריפו כדי לפתוח אותו בלי חלון קונסולה, או הריצו זאת ישירות לאבחון:

```powershell
powershell -File desktop\WintageInstaller.ps1
```

רשימת נושאים עם שבבי צבע, היעדים שנמצאו במחשב הזה, תצוגה מקדימה חיה של Win95, וכל עשרים ואחד אסימוני הצבע כדוגמיות הניתנות לעריכה. עריכת כל דוגמית מבקעת את הפלטה ל-**Custom** במקום לשנות נושא שנשלח מתחתיך. הפאנל מימין מציג ניגודיות WCAG חיה לשלושת האסימונים הנושאים טקסט — פלטה שנכשלת שם נדחית ממילא על ידי שער הבנייה, אז עדיף לראות אותה לפני Apply מאשר אחרי.

היעדים מחולקים לשתי רשימות הניתנות לניווט במקלדת: **MY APPS** מכילה את כלי CodeNomad, SAIPENVIEW, SmartVac ו-WildRift הניידים/ממקור-עץ; **POPULAR APPS** מכילה Windows, OBS, מסופים, עורכים ושאר התוכנה המותקנת. ALL/NONE ו-Apply/Revert פועלים על פני שתי הרשימות מבלי לשנות את החלוקה.

החלון לובש את הפלטה שהוא עומד להתקין. זו התצוגה המקדימה המהירה ביותר שקיימת, והיא שומרת על הכלי ישר: פלטה שהופכת את החלון הזה לבלתי קריא היא בלתי קריא באופן נראה לעין.

Apply יוצא אל `install.ps1`. יש בדיוק נתיב קוד אחד שמתקין נושא, כך שה-GUI לא יכול לסטות משורת הפקודה.

## שורת הפקודה

```powershell
.\desktop\install.ps1                                  # מה יש כאן, מה מעוצב, עם איזו פלטה
.\desktop\install.ps1 -Target freebuff -Palette klite  # אפליקציה אחת, פלטה אחת
.\desktop\install.ps1 -Target all -Palette goldendefault # הכול
.\desktop\install.ps1 -Target all -WhatIf              # תגיד מה ישתנה, אל תיגע בכלום
.\desktop\install.ps1 -Target freebuff -Revert         # בטל אחד
```

ברירת המחדל של `-Palette` היא `goldendefault` (**Golden Default**). ה-GUI נפתח על אותה פלטה ובודק כל יעד זמין. צביעה חוזרת של אפליקציה שכבר מעוצבת עובדת בזמן שהיא רצה; התקנה ראשונה לא, כי הארכיון בשימוש.

### הסרת פרסומות FreeBuff

FreeBuff (אפליקציית שולחן העבודה של העוזר מבוסס הבינה המלאכותית) מגיעה עם רשת פרסומות משלה: חבילת ה-renderer (`resources/orchestrator/ui/assets/index-*.js`) מרנדרת כרטיס `sponsored-ad` ובאנר שרשור, וה-orchestrator (`resources/orchestrator/orchestrator.js`) חושף נתיבי `/api/ad/slot|impression|click` שקוראים למכרז הפרסומות המרוחק. ה-shim רק נותן נושא לאפליקציה; הוא לא נוגע בקבצים האלה.

`desktop/patch-freebuff-ads.js` חותך את הפרסומות החוצה ברמת הבית:

- renderer: נקודות הקריאה של כרטיס/באנר הפרסומת הופכות ל-`null`, ומתודות לקוח ה-API `adSlot` / `adImpression` / `adClick` הופכות ל-no-op — שום דבר לא מרנדר, ושום בקשה `/api/ad/*` לא יוצאת מה-renderer;
- orchestrator: כל שלושת נתיבי `/api/ad/*` מפסיקים לקרוא לרשת הפרסומות, ובקשת הפרסומות המובנית בסיבוב החי (`maybeRequestAd`) מקוצרת.

שם קובץ החבילה מטמיע hash בנייה, אז הטלאי מגלה את החבילה הנוכחית מ-`index.html` במקום לשלוח מטען נעול-גרסה — זה מה שגורם לו לשרוד עדכונים. המקוריים מגובים ל-`_orig-backup-<timestamp>/` בתיקיית ההתקנה; `--revert` משחזר את החדש ביותר.

**גרסאות עתידיות מטופלות בשתי שכבות עצמאיות:**

1. **טלאי בית עם גיבויי regex.** לכל יעד יש מחרוזת מדויקת לבנייה הנוכחית *וגיבוי ביטוי רגולרי* המעוגן במה שמיניפייר לא יכול לשנות שם — האותיות של הנתיב `/api/ad/*`, מבחין הפרוטוקול `case"ad":`, המחלקה `sponsored-ad`, והמיקומים `variant:"banner"` / `variant:"card"`. ה-orchestrator לא ממוזער (שמות קריאים כמו `maybeRequestAd` ו-`app.ads.slotAd`), אז המחרוזות המדויקות שלו מחזיקות לאורך זמן; חבילת ה-renderer ממוזערת, אז גיבויי ה-regex שלה משתלטים ברגע שהבנייה הבאה משנה שם למזהים.
2. **חסימה ברמת shim (`targets/electron/shim.cjs`).** עצמאי לחלוטין מהחבילה: כל fetch/XHR לכתובת `/api/ad/` נדחה בתוך הדף, וכל רכיב שהמחלקה שלו מכילה `sponsored-ad` מוסתר ברגע שהוא מופיע. אפילו חבילה חדשה לגמרי שהסקריפט הזה עוד לא למד אינה יכולה להעלות פרסומת.

```powershell
node .\desktop\patch-freebuff-ads.js           # patch (מגבה קודם)
node .\desktop\patch-freebuff-ads.js --sound "C:\...\my.mp3"   # patch + צליל סיום מותאם (wav/mp3/ogg/flac/m4a/aac)
node .\desktop\patch-freebuff-ads.js --scan    # אילו סמני פרסומות הבנייה הזאת נושאת?
node .\desktop\patch-freebuff-ads.js --verify
node .\desktop\patch-freebuff-ads.js --revert
```

הוא רץ אוטומטית כחלק מ-`install.ps1 -Target freebuff`, וחובה להריץ אותו שוב אחרי כל עדכון של FreeBuff (עדכונים משחזרים את קבצי המלאי). אם בנייה משנה צורה, הסקריפט מציין את היעד שכבר לא תואם — הריצו `--scan` כדי לראות מה הבנייה החדשה עדיין נושאת ולרענן את המחרוזות שם.

**צליל הסיום של FreeBuff.** ה-renderer מנגן `chime-<hash>.mp3` כשסיבוב מסתיים. הטלאי מוצא אותו באותה דרך שהוא מוצא את החבילה (השם מטמיע hash בנייה), אז `--sound <file>` מתקין את האודיו שלכם (wav/mp3/ogg/flac/m4a/aac) מעליו ושומר את קובץ המלאי כ-`chime-*.mp3.bak`; `--revert` משחזר אותו. `--verify` מדווח איזה מהם חי.

### כפתור הצליל של FreeBuff (GUI)

ל-`WintageInstaller.ps1` יש כפתור קטן **FB SOUND** מתחת לערימת APPLY / REVERT. הוא רק מאחסן *העדפה*; `install.ps1 -Target freebuff` קורא את אותו קובץ ומעביר אותו לטלאי כ-`--sound`, כך שהפרסומות והצליל מוחלים בריצה אחת:

- **קליק שמאלי** — בחרו קובץ אודיו (OpenFileDialog, wav/mp3/ogg/flac/m4a/aac) ותשמעו אותו מושמע מיד: PCM WAV דרך System.Media.SoundPlayer, כל פורמט אחר דרך WPF MediaPlayer (Media Foundation, אסינכרוני, כך שהחלון לעולם לא קופא). הבחירה נשמרת ב-`%APPDATA%\Wintage\freebuff-sound.txt` (לכל מכונה, מחוץ ל-checkout של git, בדיוק כמו תיקיות מקור-העץ שנשמרו).
- **קליק ימני** — נקה את ההעדפה חזרה לצלצול המלאי של FreeBuff (וגם עוצר כל תצוגה מקדימה שעדיין מנוגנת).
- **COPY** — מעתיק את האודיו שנבחר לתוך הריפו עצמו (`sounds\freebuff.<ext>`, תוך שמירת סיומת המקור) ומפנה מחדש את ההעדפה לעותק הזה, כך שהצליל שורד מחיקה או הזזה של הקובץ המקורי. מופעל רק בזמן שצליל מותאם מוגדר; העתקה חוזרת פשוט דורסת את עותק הריפו. תיקיית `sounds/` היא תוכן רגיל הניתן למעקב git, כך שביצוע commit עבורה גורם לצליל לשרוד גם שכפולים מחדש.

רק מכלי אודיו מוכרים מוצגים בתצוגה מקדימה — הכותרת נבדקת קודם, כך שבחירה שאינה אודיו מוכרזת במקום להשמיע שום דבר בשקט.

הכפתור קורא `ON` בזמן שצליל מותאם מוגדר; ריחוף מעליו מציג את הנתיב. החילו את יעד ה-`freebuff` לאחר מכן (סמנו FreeBuff + APPLY, או הריצו `install.ps1 -Target freebuff` ממסוף) כדי שייכנס לתוקף.

### מסופים

`terminal` כותב סכמת צבע `Wintage` לתוך כל קובץ הגדרות Windows Terminal מזוהה — יציב, Preview או לא-ארוז — ובוחר אותה דרך `profiles.defaults`, יחד עם Consolas 12 בטוח-מסוף וטקסט aliased. הקובץ המקורי נשמר בית-אחר-בית לצידו ו-`-Revert` משחזר אותו.

`conhost` מכסה `cmd.exe` קלאסי, Windows PowerShell, פרופילי קונסולת Git CMD/Bash, ושאר בני `HKCU\Console` קיימים. הוא כותב את טבלת 16 הצבעים המלאה של הפלטה גם לברירות המחדל השורשיות וגם לכל עקיפה קיימת, ואז משחזר רק את הערכים שנגע בהם. הוא מחיל שם גם Consolas, כי Verdana הפרופורציונלית מתנגשת בתוך רשת התאים ברוחב הקבוע שבה שני מארחי המסוף משתמשים.

### דפדפנים ו-Tampermonkey

`browsers` מוצא פרופילי Chrome, Edge, Brave, Cent, Vivaldi ו-Opera ממיקומים מותקנים ומשורש נייד שאתם מפנים אליו (`-PortableRoot`, או ערך `portable` שנשמר ב-`paths.json`). הסטטוס שלו מציג גם את מספר הפרופילים וגם כמה מהם מכילים Tampermonkey. Apply מעתיק את נושא ה-chrome שנבחר לתיקייה היציבה `%LOCALAPPDATA%\Wintage\browser-theme`, מניח את הנתיב הזה בלוח, ופותח כל פרופיל מדויק ב-`chrome://extensions` יחד עם דף Install/Update של סקריפט המשתמש Wintage. פרופילים ללא Tampermonkey מקבלים גם את דף ה-Chrome Web Store שלו.

Chromium אוסר בכוונה התקנת הרחבות אילמת מחוץ לחנות במכונת Windows שאינה מנוהלת. לכן התקנת נושא הדפדפן הראשונה דורשת אישור **Developer mode → Load unpacked** אחד לכל פרופיל. בחרו את הנתיב שהועתק; אחר כך Wintage ממשיך להחליף את אותה תיקייה יציבה כשפלטות משתנות. אישרו גם **Install/Update** ב-Tampermonkey. שום קובץ `Preferences`, Secure Preferences או LevelDB של Tampermonkey לא נערך מאחורי גבו של הדפדפן. אם Tampermonkey לא היה נוכח, התקינו אותו מלשונית החנות שנפתחה ורעננו את לשונית `wintage.user.js` הפתוחה כדי לקבל את מסך Install.

### Windows

`windows` מתקין ומפעיל מיד נושא עם כתובת-תוכן `%LOCALAPPDATA%\Microsoft\Windows\Themes\Wintage-<hash>.theme`. הוא מתחיל מהנושא הפעיל ומחליף רק את קטעי הצבע, הסמן והסגנון החזותי המתועדים. הטפט, הצלילים ואייקוני שולחן העבודה נשארים ללא שינוי; הסמנים עוברים בכוונה לסכמת `___CURRENT___` המותקנת. הנושא הפעיל הראשון נשמר בית-אחר-בית כ-`Wintage.original.theme`; שינויי פלטה שומרים על קו הבסיס הזה, ו-`-Revert` מפעיל אותו שוב. פקדי Windows מודרניים עדיין מגיעים מסגנון ה-Aero החתום — Wintage משנה את המצב הכהה, ה-accent ומכניסות צבעי המערכת הקלאסיות שהוא תומך בהן במקום להחליף קבצי `.msstyles` מוגנים. כיתובי חלון פעילים ולא פעילים חולקים את צבע המשטח הבולט העמום של הפלטה; ההדגשה הבהירה שמורה לקצוות טקסט/בחירה. הדגשת הכיתוב הלא-פעיל הקודם מצולמת בנפרד ומשוחזרת במדויק על ידי `-Revert`. hash התוכן נותן ל-Windows יעד קישור קבצים חדש כשהפלטה עצמה נבנית מחדש, כך שהחלה חוזרת של פלטה מעודכנת אינה נטעית כ-no-op; קובץ ה-Wintage שהוחלף מוסר לאחר ש-Windows מאשר שהחדש פעיל.

### OBS Studio

`obs` יוצר גרסת OBS 30.2+ על בסיס Yami Classic המתוחזק, מתקין אותה ל-`%APPDATA%\obs-studio\themes`, וכותב את מזהה הנושא היציב ל-`user.ini`, כך שהפלטה הנבחרת של Wintage כבר נבחרה בהשקה הבאה. סגרו את OBS לפני Apply או Revert: OBS כותב מחדש את `user.ini` ביציאה. ההחלה הראשונה מגבה גם את הבחירה הקודמת וגם כל נושא בעל שם זהה בית-אחר-בית.

### אפליקציות Electron

`resources/app.asar` מועבר ל-`resources/app/app.asar` (האח `app.asar.unpacked` שלו עובר איתו — הצימוד הזה הוא לפי שם קובץ, והפרדתו שוברת כל מודול native), ו-`shim.cjs` קטן תופס את משבצת ה-`resources/app` שהתפנתה. ה-shim מזריק את גיליון הסגנונות ואז טוען את הארכיון המקורי. **שום בייט של אפליקציה לא נכתב מחדש**, רק מועבר למקום אחר; `-Revert` מחזיר אותו ישר.

גיליון הסגנונות לא כתוב עבור האפליקציות האלה — הוא מופק מ-`wintage.user.js`, כך שכל תיקון שפה, פס גלילה או סולם טיפוגרפי שנעשה לדפדפן נוחת גם כאן, בלי עותק שני שיוכל להרקיב.

שתי הערות שכדאי לדעת מראש:

- הגישה הברורה — להשליך `resources/app` ליד הארכיון ולסמוך על כך ש-Electron יעדיף אותו — **לא עובדת ונכשלת בשקט**. Electron מחפש את `app.asar` קודם. האפליקציה מתחילה בצורה מושלמת והנושא לעולם לא רץ.
- ה-shim הוא `.cjs`, לא `.js`, בכוונה. ה-`package.json` שלו מועתק משל האפליקציה עצמה כדי שהאפליקציה תשמור על שמה ועל גרסתה (השם קובע היכן גר userData — shim שמשנה אותו מעביר את האפליקציה לפרופיל ריק). אם המניפסט הזה אומר `"type": "module"`, shim מסוג `.js` מת על ה-`require` הראשון שלו.

### אפליקציית שולחן העבודה של Claude: במקום, והמסגרת שבה היא באמת מציירת

Claude לא יכול להשתמש בהעברה שלעיל, כי `OnlyLoadAppFromAsar` מרותך דולק — Electron טוען את `resources/app.asar` ושום דבר אחר, כך ש-shim ב-`resources/app` לעולם לא יכול לרוץ. הוא מטולא **במקום** במקום זאת: הארכיון מגובה, ה-`main` ב-`package.json` שלו נכתב מחדש ל-`"../wintage-shim.cjs"` (מרופד לאותו אורך בית, כך שכל היסט בארכיון נשאר תקף), ו-hash השלמות לכל קובץ מעודכן כך שיתאים. `-Revert` משחזר את הגיבוי.

המתקין עדיין קורא את הפיוזים **לפני שהוא מזיז משהו** ומסרב עם סיבה כשהם חוסמים — `EnableEmbeddedAsarIntegrityValidation` הייתה גורמת לכתיבה מחדש שלעיל להיכשל בהשקה ולא בהתקנה. בדקו כל אפליקציה בעצמכם:

```powershell
node ..\tools\electron-fuses.js "<path to the app's exe>"
```

החצי השני של זה היה בעיה שקטה בהרבה. ה-`BrowserWindow` של Claude מרנדר קליפה דקה ו**כל האפליקציה הנראית היא `WebContentsView`** המחוברת אליה. ה-shim נהג לחבר `browser-window-created`, אז הוא הזריק את גיליון הסגנונות לקליפה, דיווח על הצלחה ל-`wintage-status.txt`, ולא שינה שום דבר שאתם יכולים לראות. עכשיו הוא מתחבר ל-`web-contents-created`, שמכסה גם תוכן חלונות, `WebContentsView`, `BrowserView`, אורחי `<webview>` וגם פופ-אפים.

### Obsidian

נושא קהילה נכתב לתוך `.obsidian/themes/` של כל קמרון — כל שש עשרה הפלטות בבת אחת, בדיוק כמו יעד ה-VS Code, כך שאתם עוברים ביניהן ב-**Settings → Appearance** בלי להריץ שום דבר שוב. התבנית נגזרה מהנושא הידני `VintageWin95` שכבר קיים בקמרון, כל צבע הוחלף באסימון שהוא השווה לו. `-Palette <slug>` קובע איזה מהם פעיל בהתקנה; `appearance.json` מגובה קודם, ו-`-Revert` מסיר רק את נושאי `Wintage *` ומשחזר את הבחירה הקודמת שלכם — נושא ידני באותו קמרון לעולם לא נגעים.

### SAIPENVIEW

הפרונטאנד שלו כבר מצהיר על שמות אסימוני Wintage ב-`:root` שלו, אז הטלאי הזה כותב מחדש **רק את ערכי האסימונים** — לעולם לא בורר, גופן, רוחב גבול או ריפוד. שום דבר שמשפיע על מודל התיבה לא משתנה, כך שהטקסט לא יכול לזוז. זה מכוון: הגישה הקודמת ערמה את גיליון הסגנונות של הדפדפן כולו מלמעלה, ו-`wintage.css` כתוב לדפי אינטרנט שרירותיים — בוררים אוניברסליים שכופים את הגופן, סולם הגדלים, גבולות 2px וגבהי פקדים. באפליקציה שכבר יש לה פריסה משלה, זה מזיז הכול.

מאומת על ידי הסוואת כל hex והשוואת diff מול הגיבוי: זהה מבחינה מבנית, רק ליטרלי צבע נבדלים. `--link` מדווח כלא-מוצהר שם (קישורי ה-markdown שלו קוראים `--accentTeal`, שזה כן מגדיר) במקום להיות מוזרק — הוספת משתנה שהאפליקציה אף פעם לא קוראת היא משקל מת.

### MPC-HC (K-Lite)

Win32 ילידית, בלי גיליון סגנונות ובלי נקודת הזרקה, והצבעים של הנושא הכהה שלה מהודרים בתוך התוכנה — שום ערך רישום לא חושף אותם. אז היעד הזה **לא יכול לשאת פלטה**. מה שהוא כן עושה: מפעיל את הנושא הכהה ומחיל את כללי הטיפוגרפיה של UI.md על ה-OSD, שהוא המשטח היחיד ש-MPC-HC נותן למשתמש לשלוט בו. ההגדרות הקודמות מיוצאות ל-`desktop/backup/mpc-hc-settings.reg` קודם.

סגרו את MPC-HC לפני ההחלה: הוא כותב מחדש את ההגדרות שלו ביציאה.

## בנייה מחדש

הכול תחת `desktop/out/` מופק מ-`themes/*.json`. הוא לא במעקב git (T-160), אז שיבוט טרי חייב לבנות אותו פעם אחת לפני ההתקנה:

```powershell
node ..\tools\build-desktop.js          # בנה מחדש את כל היעדים
node ..\tools\build-desktop.js --check  # exit 1 אם משהו מעופש
```

`release.ps1` מריץ את הבנייה ואת כל השערים, כך שיציאה לא יכולה לשלוח פלט שנסחף מהפלטות.
