# Wintage для десктопных приложений

Скрипт темизирует веб. А это темизирует программы вокруг него — из тех же
палитр, чтобы браузер и приложения перестали спорить, что такое «тёмное золото».

За каждым решением тут одно правило: **приложения обновляются сами, и обновление
не имеет права молча что-то ломать.** Есть у таргета место в твоём собственном
профиле — тема ставится туда и переживает обновления. Нет места — установщик
написан так, чтобы его можно было перезапускать, — и честно про это говорит,
а не притворяется, что всё сохранилось.

## GUI

Двойной щелчок по **`Wintage Installer.vbs`** в корне репозитория — откроется без
окна консоли. Для диагностики гоняй напрямую:

```powershell
powershell -File desktop\WintageInstaller.ps1
```

Список тем с цветными чипами, найденные на этой машине таргеты, живой превью
Win95 и все двадцать один цветовой токен как редактируемые свотчи. Покрутил любой
свотч — палитра разветвилась в **Custom**, а не подменилась под тебя внутри
поставляемой темы. Панель справа показывает живой контраст WCAG по трём токенам,
что несут текст — палитру, которая там провалилась, сборочный шлюз всё равно
не пропустит, так что лучше увидеть это до Apply, чем после.

Таргеты разбиты на два списка, до которых дотянешься с клавиатуры: **MY APPS** —
портативные/исходники CodeNomad, SAIPENVIEW, SmartVac и WildRift; **POPULAR APPS** —
Windows, OBS, терминалы, редакторы и прочее установленное ПО.
ALL/NONE и Apply/Revert работают по обоим спискам, не трогая их группировку.

Окно одето в палитру, которую собирается ставить. Это самый быстрый превью из
доступных, и он держит инструмент честным: палитра, от которой это окно стало
нечитаемым, — видно невооружённым глазом.

Apply выплёвывает вызов в `install.ps1`. Ровно один путь кода ставит тему, так что
GUI не может разойтись с командной строкой.

## Командная строка

```powershell
.\desktop\install.ps1                                  # что есть, что темизировано, какой палитрой
.\desktop\install.ps1 -Target freebuff -Palette klite  # одно приложение, одна палитра
.\desktop\install.ps1 -Target all -Palette goldendefault # всё разом
.\desktop\install.ps1 -Target all -WhatIf              # покажи, что изменится, ничего не трогай
.\desktop\install.ps1 -Target freebuff -Revert         # откати одно
```

`-Palette` по умолчанию `goldendefault` (**Golden Default**). GUI открывается на
той же палитре и проверяет каждый доступный таргет. Перекраска уже
тематизированного приложения работает, пока оно запущено; первая установка — нет,
потому что архив занят.

## Что каждый таргет реально может темизировать

| target | mechanism | survives an app update |
|---|---|---|
| `windows` | пользовательский `.theme`: тёмный режим системы/приложений, акцент и классические роли цветов | yes — ставится в твою локальную папку Windows Themes |
| `browsers` | находит установленные и портативные профили Chromium, готовит выбранную тему браузера и открывает страницы подтверждения Tampermonkey/темы, которыми владеет браузер | yes после одного **Load unpacked** на профиль |
| `terminal` | схема Windows Terminal + дефолты всех профилей, Consolas 12 со сглаживанием | yes — настройки в твоём профиле |
| `conhost` | дефолты `HKCU\Console` + каждый существующий профиль cmd/PowerShell | yes — снапшот только тронутых значений |
| `obs` | вариант `.ovt` для OBS 30.2+ + активный ID темы в `user.ini` | yes — живёт в твоём профиле |
| `antigravity`, `vscode` | расширение цветовой темы в `~/.antigravity/extensions` / `~/.vscode/extensions` | **yes** — живёт в твоём профиле |
| `freebuff`, `antigravity-app`, `codenomad` | Electron-шим, см. ниже | no — перезапусти установщик |
| `claude` | Electron-шим, патчится на месте — см. ниже | no — обновление создаёт новую папку `app-<version>` |
| `mpchc` | реестр, только тёмная тема + типографика OSD | no — MPC-HC переписывает свои настройки при выходе |
| `obsidian` | коммьюнити-тема в каждый vault, все палитры ставятся разом | **yes** — живёт в твоём vault |
| `saipenview` | переписывает значения своих токенов `:root` в `style.css` | no — это исходник; перезапусти после pull |
| `discord` | CSS кидается в собственную папку тем BetterDiscord | yes |
| `totalcmd`, `totalcmd2` | ключи `[Colors]` в `wincmd.ini`; существующие фильтры свежих файлов используют цвет ссылки палитры | yes — это твой ini |
| `smartvac`, `wildrift` | таблица токенов переписывается в собственном исходнике приложения | no — это исходник; перезапусти после pull |

### Вырезание рекламы FreeBuff

FreeBuff (десктопное приложение AI-ассистента) таскает свою собственную
рекламную сеть: рендер-бандл (`resources/orchestrator/ui/assets/index-*.js`)
рисует карточку `sponsored-ad` и баннер в треде, а оркестратор
(`resources/orchestrator/orchestrator.js`) выставляет маршруты
`/api/ad/slot|impression|click`, которые зовут удалённый рекламный аукцион.
Шим только темизирует приложение; те файлы он не трогает.

`desktop/patch-freebuff-ads.js` вырезает рекламу побайтно:

- рендер: точки вызова карточки/баннера становятся `null`, а клиентские методы
  API `adSlot` / `adImpression` / `adClick` — пустышками — ничего не рисуется,
  и ни один запрос `/api/ad/*` не покидает рендер;
- оркестратор: все три маршрута `/api/ad/*` перестают звать рекламную сеть,
  а инлайн-запрос рекламы в живом ходе (`maybeRequestAd`) закорачивается.

В имя бандла зашит хеш сборки, поэтому патч находит текущий бандл из `index.html`,
а не везёт payload, прибитый к версии — именно это и позволяет ему переживать
обновления. Оригиналы бэкапятся в `_orig-backup-<timestamp>/` в каталоге
установки; `--revert` восстанавливает самый свежий.

**Будущие версии обрабатываются на двух независимых слоях:**

1. **Байтовый патч с regex-запасными.** У каждого таргета есть точная строка под
   текущую сборку *и* регулярное выражение на запас, заякоренное на то, что
   минификатор переименовать не может — литералы пути `/api/ad/*`, дискриминатор
   протокола `case"ad":`, класс `sponsored-ad` и позиции `variant:"banner"` /
   `variant:"card"`. Оркестратор не минифицирован (читаемые имена вроде
   `maybeRequestAd` и `app.ads.slotAd`), так что его точные строки живут долго;
   рендер-бандл минифицирован, поэтому его regex-запасы вступают в силу в момент,
   когда следующая сборка переименует идентификаторы.
2. **Блок на уровне шима (`targets/electron/shim.cjs`).** Полностью независим от
   бандла: любой fetch/XHR по URL `/api/ad/` отклоняется внутри страницы, а любой
   элемент с классом, содержащим `sponsored-ad`, прячется в момент появления.
   Даже новенький бандл, которого этот скрипт ещё не учил, не сможет показать
   рекламу.

```powershell
node .\desktop\patch-freebuff-ads.js           # патч (сначала бэкап)
node .\desktop\patch-freebuff-ads.js --sound "C:\...\my.mp3"   # патч + свой звук завершения (wav/mp3/ogg/flac/m4a/aac)
node .\desktop\patch-freebuff-ads.js --scan    # какие рекламные маркеры несёт ЭТА сборка?
node .\desktop\patch-freebuff-ads.js --verify
node .\desktop\patch-freebuff-ads.js --revert
```

Он запускается автоматически как часть `install.ps1 -Target freebuff` и должен
перезапускаться после каждого обновления FreeBuff (обновления восстанавливают
стоковые файлы). Сменила сборка форму — скрипт назовёт таргет, который перестал
совпадать: гоняй `--scan`, смотри, что ещё несёт новая сборка, и обновляй строки.

**Звук завершения FreeBuff.** Рендер играет `chime-<hash>.mp3`, когда ход
заканчивается. Патч находит его так же, как бандл (в имя зашит хеш сборки),
так что `--sound <file>` кладёт поверх твой собственный звук
(wav/mp3/ogg/flac/m4a/aac) и хранит стоковый как `chime-*.mp3.bak`; `--revert`
восстанавливает его. `--verify` докладывает, какой сейчас живой.

### Кнопка звука FreeBuff (GUI)

В `WintageInstaller.ps1` есть маленькая кнопка **FB SOUND** под стеком
APPLY / REVERT. Она хранит только *предпочтение*; `install.ps1 -Target freebuff`
читает тот же файл и передаёт его патчу как `--sound`, так что реклама и звук
применяются одним прогоном:

- **Левый клик** — выбираешь аудиофайл (OpenFileDialog, wav/mp3/ogg/flac/m4a/aac)
  и слышишь его сразу же: PCM WAV через System.Media.SoundPlayer, все остальные
  форматы через WPF MediaPlayer (Media Foundation, асинхронно — окно никогда не
  замирает). Выбор запоминается в
  `%APPDATA%\Wintage\freebuff-sound.txt` (на машину, вне git-чекаута, ровно как
  запомненные папки исходников).
- **Правый клик** — сбрасывает предпочтение обратно на стоковый чейм FreeBuff
  (и глушит превью, если ещё играет).
- **COPY** — копирует выбранный звук прямо в репозиторий
  (`sounds\freebuff.<ext>`, сохраняя исходное расширение) и перенацеливает
  предпочтение на эту копию, так что звук переживает удаление или перенос
  исходного файла. Включена, только пока задан кастомный звук; повторное
  копирование просто перезаписывает копию в репо. Папка `sounds/` — обычный
  git-трекаемый контент: закоммитил — звук переживёт и переклонирование.

Превью получают только распознанные аудиоконтейнеры — сперва нюхается заголовок,
так что не-аудио выбор объявляется вслух, а не молча играет тишину.

Кнопка горит `ON`, пока задан кастомный звук; наведение показывает путь. Примени
после этого таргет `freebuff` (галочка на FreeBuff + APPLY, или гоняй
`install.ps1 -Target freebuff` из терминала) — чтобы он заработал.

### Терминалы

`terminal` пишет цветовую схему `Wintage` в каждый найденный файл настроек
Windows Terminal — стабильный, Preview или распакованный — и выбирает её через
`profiles.defaults`, вместе с консоль-безопасной Consolas 12 и сглаженным
текстом. Оригинал файла хранится байт-в-байт рядом, `-Revert` его
восстанавливает.

`conhost` покрывает классический `cmd.exe`, Windows PowerShell, консольные
профили Git CMD/Bash и прочие существующие дети `HKCU\Console`. Пишет полную
16-цветную таблицу палитры и в корневые дефолты, и в каждый существующий
оверрайд, а восстанавливает только те значения, что трогал. Consolas ставит и
туда, потому что пропорциональная Verdana коллизит внутри сетки
фиксированной ширины, которую используют оба терминальных хоста.

### Браузеры и Tampermonkey

`browsers` находит профили Chrome, Edge, Brave, Cent, Vivaldi и Opera в
установленных местах и в портативном корне, на который укажешь
(`-PortableRoot` или запомненная запись `portable` в `paths.json`). Статус
показывает и число профилей, и сколько из них с Tampermonkey. Apply копирует
выбранную тему браузера-хрома в стабильную папку
`%LOCALAPPDATA%\Wintage\browser-theme`, кладёт этот путь в буфер обмена и
открывает каждый конкретный профиль на `chrome://extensions` плюс страницу
установки/обновления юзерскрипта Wintage. Профили без Tampermonkey получают ещё
и его страницу в Chrome Web Store.

Chromium намеренно запрещает тихую установку расширений не из магазина на
неуправляемой Windows-машине. Поэтому первая установка темы браузера требует
одно подтверждение **Developer mode → Load unpacked** на профиль. Выбираешь
скопированный путь; после этого Wintage просто продолжает перезаписывать ту же
стабильную папку при смене палитр. Подтверди в Tampermonkey и **Install/Update**
тоже. Никакой файл браузера `Preferences`, Secure Preferences или LevelDB
Tampermonkey не редактируется за спиной браузера. Не было Tampermonkey — ставь
из открытой вкладки магазина и обнови уже открытую вкладку `wintage.user.js`,
чтобы получить экран установки.

### Windows

`windows` ставит и тут же активирует контент-адресуемый
`%LOCALAPPDATA%\Microsoft\Windows\Themes\Wintage-<hash>.theme`. Стартует с
активной темы и заменяет только документированные секции цветов, курсоров и
визуального стиля. Обои, звуки и иконки рабочего стола не трогаются; курсоры
намеренно переключаются на установленную схему `___CURRENT___`. Первая активная
тема сохраняется байт-в-байт как `Wintage.original.theme`; смена палитр держит
этот базис, а `-Revert` активирует его снова. Современные элементы Windows
по-прежнему приходят из подписанного визуального стиля Aero — Wintage меняет
его поддерживаемый тёмный режим, акцент и классические вводы системных цветов,
а не заменяет защищённые `.msstyles`. Активные и неактивные подписи окон делят
приглушённый приподнятый цвет поверхности палитры; яркая подсветка остаётся
зарезервирована за текстом/краями выделения. Прежний акцент неактивной подписи
снапшотится отдельно и восстанавливается `-Revert` ровно. Хеш контента даёт
Windows новую цель ассоциации файла, когда та же палитра пересобирается, — так
повторное применение обновлённой палитры не принимается за no-op; замещённый
файл Wintage удаляется после того, как Windows подтвердит, что новый активен.

### OBS Studio

`obs` генерирует вариант OBS 30.2+ поверх поддерживаемой базы Yami Classic,
ставит его в `%APPDATA%\obs-studio\themes` и пишет его стабильный ID темы в
`user.ini`, так что выбранная палитра Wintage уже выбрана при следующем запуске.
Закрой OBS до Apply или Revert: OBS переписывает `user.ini` при выходе. Первый
apply бэкапит байт-в-байт и прежний выбор, и любую одноимённую тему.

### Electron-приложения

`resources/app.asar` переносится в `resources/app/app.asar` (его сосед
`app.asar.unpacked` едет вместе с ним — эта пара связана по имени файла, и
разлучить её значит сломать каждый нативный модуль), а маленький `shim.cjs`
занимает освободившийся слот `resources/app`. Шим вставляет таблицу стилей и
потом грузит оригинальный архив. **Ни один байт приложения не переписывается**,
только перемещается; `-Revert` возвращает всё на место.

Таблица стилей для этих приложений не пишется — она извлекается из
`wintage.user.js`, так что каждый починенный для браузера фаск, скроллбар и
типографская лесенка ложится и сюда, без второй копии, которая будет гнить.

Две заметки, которые полезно знать заранее:

- Очевидный путь — кинуть `resources/app` рядом с архивом и надеяться, что
  Electron предпочтёт его — **не работает и проваливается молча**. Electron
  ищет `app.asar` первым. Приложение стартует прекрасно, тема не работает
  никогда.
- Шим — `.cjs`, а не `.js`, намеренно. Его `package.json` скопирован из
  собственного файла приложения, чтобы приложение сохранило имя и версию (имя
  решает, где живёт userData — шим, который его переименует, перенесёт
  приложение в пустой профиль). Если манифест говорит `"type": "module"`,
  `.js`-шим умирает на первом же `require`.

### Десктопное приложение Claude: на месте, и рамка, в которой оно реально рисует

Claude не может использовать перенос выше, потому что `OnlyLoadAppFromAsar`
запаян намертво: Electron грузит `resources/app.asar` и ничего больше, так что
шим в `resources/app` не запустится никогда. Вместо этого он патчится **на
месте**: архив бэкапится, его `main` в `package.json` переписывается на
`"../wintage-shim.cjs"` (добивается до той же длины в байтах, чтобы каждый
офсет в архиве остался валиден), и целостностный хеш файла обновляется под
новое. `-Revert` восстанавливает бэкап.

Установщик всё ещё читает фьюзы **до того, как что-либо двигает**, и
отказывается с объяснением причины, когда они блокируют —
`EnableEmbeddedAsarIntegrityValidation` уронил бы переписывание выше на запуске,
а не на установке. Проверь любое приложение сам:

```powershell
node ..\tools\electron-fuses.js "<путь к exe приложения>"
```

Вторая половина этого была куда тише. `BrowserWindow` у Claude рисует тонкую
оболочку, а **вся видимая часть приложения — это `WebContentsView`**, прицепленный
к ней. Шим раньше хукал `browser-window-created`, так что впрыскивал таблицу
стилей в оболочку, докладывал успех в `wintage-status.txt` — и ничего
видимого не менял. Теперь он хукает `web-contents-created`, который покрывает
и содержимое окна, и `WebContentsView`, и `BrowserView`, и гостей `<webview>`,
и попапы.

### Obsidian

Коммьюнити-тема пишется в `.obsidian/themes/` каждого vault — все шестнадцать
палитр разом, ровно как таргет VS Code, так что переключаешься между ними в
**Settings → Appearance** без единого перезапуска. Шаблон выведен из рукодельной
темы `VintageWin95`, которая уже в vault: каждый цвет заменён токеном, которому
он равнялся. `-Palette <slug>` задаёт, какая активна при установке;
`appearance.json` сначала бэкапится, а `-Revert` снимает только темы
`Wintage *` и восстанавливает твой прежний выбор — рукодельная тема в том же
vault не трогается никогда.

### SAIPENVIEW

Его фронтенд уже объявляет имена токенов Wintage в своём собственном `:root`,
так что патч переписывает **только значения токенов** — ни селектор, ни шрифт,
ни ширину границы, ни padding. Ничто, что влияет на блочную модель, не меняется,
поэтому текст не может сдвинуться. Это намеренно: прежний подход наваливал сверху
целую таблицу стилей браузера, а `wintage.css` написан под произвольные веб-
страницы — универсальные селекторы, продавливающие шрифт, лесенку размеров,
границы в 2px и высоты контролов. На приложении, у которого своя вёрстка, это
сдвигает всё.

Проверено маскированием каждого hex и диффом с бэкапом: структурно идентично,
различаются только литералы цветов. `--link` докладывается как незаявленный там
(его markdown-ссылки читают `--accentTeal`, а его-то этот патч задаёт), а не
впрыскивается — добавить переменную, которую приложение не читает, было бы
мёртвым весом.

### MPC-HC (K-Lite)

Нативный Win32, ни таблицы стилей, ни точки впрыска, а цвета его тёмной темы
вкомпилированы в программу — ни одно значение реестра их не отдаёт. Так что этот
таргет **не может нести палитру**. Что он делает: включает тёмную тему и
применяет правила типографики из UI.md к OSD — единственной поверхности, которую
MPC-HC даёт пользователю крутить. Прежние настройки сперва экспортируются в
`desktop/backup/mpc-hc-settings.reg`.

Закрой MPC-HC до применения: он переписывает свои настройки при выходе.

## Пересборка

Всё под `desktop/out/` генерируется из `themes/*.json`. Это не трекается в git
(T-160), так что свежий клон должен один раз собрать перед установкой:

```powershell
node ..\tools\build-desktop.js          # пересобрать все таргеты
node ..\tools\build-desktop.js --check  # выход 1, если что-то протухло
```

`release.ps1` гоняет сборку и все шлюзы, так что релиз не может уехать с
выводом, который разошёлся с палитрами.
