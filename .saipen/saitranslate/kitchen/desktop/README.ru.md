# Wintage для десктопных приложений

Юзерскрипт темизирует веб. Это темизирует программы вокруг него — из тех же
палитр, чтобы браузер и приложения перестали спорить о том, что значит тёмное
золото.

За каждым решением здесь стоит одно правило: **приложения обновляют сами себя,
и обновление не должно молча что-то ломать.** Где у таргета есть место в вашем
собственном профиле — тема ставится туда и переживает обновления. Где его нет —
установщик написан так, чтобы его можно было перезапускать, и прямо говорит об
этом, а не делает вид, что сохранил что-то навсегда.

## Графический интерфейс

Дважды щёлкните **`Wintage Installer.vbs`** в корне репозитория, чтобы открыть
его без окна консоли, либо запустите напрямую для диагностики:

```powershell
powershell -File desktop\WintageInstaller.ps1
```

Список тем с цветовыми образцами, найденные на этой машине таргеты, живой
предпросмотр Win95 и все двадцать один цветовой токен в виде редактируемых
образцов. Правка любого образца разводит палитру в **Custom**, а не меняет
поставляемую тему у вас под рукой. Панель справа показывает живой контраст WCAG
для трёх токенов, которые несут текст, — палитра, которая там не проходит,
всё равно не пройдёт сборочный шлюз, так что лучше увидеть это до ПРИМЕНИТЬ,
чем после.

Таргеты разбиты на два списка, до которых можно добраться с клавиатуры:
**МОИ ПРИЛОЖЕНИЯ** содержит портативные/исходные инструменты CodeNomad,
SAIPENVIEW, SmartVac и WildRift; **ПОПУЛЯРНЫЕ ПРИЛОЖЕНИЯ** — Windows, OBS,
терминалы, редакторы и прочее установленное ПО. ВСЕ/НИЧЕГО и
ПРИМЕНИТЬ/ОТКАТИТЬ работают по обоим спискам, не трогая их группировку.

Окно само одето в ту палитру, которую собирается установить. Это самый быстрый
из доступных предпросмотров, и он держит инструмент честным: палитра, которая
делает это окно нечитаемым, видна как нечитаемая.

ПРИМЕНИТЬ уходит в `install.ps1`. Код-путь установки темы ровно один, так что
GUI не может разойтись с командной строкой.

## Командная строка

```powershell
.\desktop\install.ps1                                  # what is here, what is themed, with which palette
.\desktop\install.ps1 -Target freebuff -Palette klite  # one app, one palette
.\desktop\install.ps1 -Target all -Palette goldendefault # everything
.\desktop\install.ps1 -Target all -WhatIf              # say what would change, touch nothing
.\desktop\install.ps1 -Target freebuff -Revert         # undo one
```

`-Palette` по умолчанию равен `goldendefault` (**Golden Default**). GUI
открывается на той же палитре и проверяет каждый доступный таргет. Перекраска
уже темизированного приложения работает, пока оно запущено; первая установка —
нет, потому что архив занят.

## Что реально можно темизировать в каждом таргете

| таргет | механизм | переживает обновление приложения |
|---|---|---|
| `windows` | пользовательский `.theme`: тёмный режим системы/приложений, акцент и классические цветовые роли | yes — устанавливается в вашу локальную папку Windows Themes |
| `browsers` | находит установленные и портативные профили Chromium, готовит выбранную тему браузера и открывает принадлежащие браузеру страницы подтверждения Tampermonkey/темы | yes — после одного **Load unpacked** на профиль |
| `terminal` | схема Windows Terminal + значения по умолчанию для всех профилей, Consolas 12 без сглаживания | yes — настройки лежат в вашем профиле |
| `conhost` | значения по умолчанию `HKCU\Console` + каждый существующий профиль cmd/PowerShell | yes — точный снимок затронутых значений |
| `obs` | вариант OBS 30.2+ `.ovt` + ID темы в активном `user.ini` | yes — живёт в вашем профиле |
| `antigravity`, `vscode` | расширение цветовой темы в `~/.antigravity/extensions` / `~/.vscode/extensions` | **yes** — живёт в вашем профиле |
| `freebuff`, `antigravity-app`, `codenomad` | шим Electron, см. ниже | no — перезапустите установщик |
| `claude` | шим Electron, патч на месте — см. ниже | no — обновление создаёт новую папку `app-<version>` |
| `mpchc` | реестр, только тёмная тема + типографика OSD | no — MPC-HC перезаписывает свои настройки при выходе |
| `obsidian` | коммьюнити-тема для каждого хранилища, все палитры устанавливаются сразу | **yes** — живёт в вашем хранилище |
| `saipenview` | переписывает собственные значения токенов `:root` в `style.css` | no — исходный файл; перезапустите после pull |
| `discord` | CSS кладётся в собственную папку тем BetterDiscord | yes |
| `totalcmd`, `totalcmd2` | ключи `[Colors]` в `wincmd.ini`; существующие фильтры недавних файлов используют цвет ссылки палитры | yes — это ваш ini |
| `smartvac`, `wildrift` | таблица токенов переписана в собственном исходнике приложения | no — исходный файл; перезапустите после pull |

### Удаление рекламы FreeBuff

FreeBuff (десктопное приложение AI-ассистента) несёт собственную рекламную сеть:
бандл рендерера (`resources/orchestrator/ui/assets/index-*.js`) рисует карточку
`sponsored-ad` и баннер в потоке диалога, а оркестратор
(`resources/orchestrator/orchestrator.js`) открывает маршруты
`/api/ad/slot|impression|click`, которые ходят в удалённый рекламный аукцион.
Шим только темизирует приложение; эти файлы он не трогает.

`desktop/patch-freebuff-ads.js` вырезает рекламу на уровне байтов:

- рендерер: точки вызова карточки/баннера становятся `null`, а методы
  API-клиента `adSlot` / `adImpression` / `adClick` становятся пустышками —
  ничего не рисуется, и ни один запрос `/api/ad/*` не покидает рендерер;
- оркестратор: все три маршрута `/api/ad/*` перестают обращаться к рекламной
  сети, а запрос встроенной рекламы в живом диалоге (`maybeRequestAd`)
  обрывается накоротко.

Имя бандла содержит хеш сборки, поэтому патч находит текущий бандл по
`index.html`, а не везёт с собой привязанную к версии начинку, — именно это и
позволяет ему переживать обновления. Оригиналы резервируются в
`_orig-backup-<timestamp>/` в каталоге установки; `--revert` восстанавливает
самый свежий.

**Будущие версии обрабатываются на двух независимых уровнях:**

1. **Байтовый патч с regex-запасными вариантами.** Для каждого таргета есть
   точная строка текущей сборки *и* запасной вариант на регулярном выражении,
   опирающийся на то, что минификатор переименовать не может, — литералы путей
   `/api/ad/*`, дискриминатор протокола `case"ad":`, класс `sponsored-ad` и
   размещения `variant:"banner"` / `variant:"card"`. Оркестратор не
   минифицирован (читаемые имена вроде `maybeRequestAd` и `app.ads.slotAd`),
   так что его точные строки держатся долго; бандл рендерера минифицирован,
   поэтому его regex-запасные варианты вступают в дело в тот момент, когда
   следующая сборка переименует его идентификаторы.
2. **Блокировка на уровне шима (`targets/electron/shim.cjs`).** Полностью
   независимо от бандла: любой fetch/XHR к URL `/api/ad/` отклоняется внутри
   страницы, а любой элемент, чей класс содержит `sponsored-ad`, скрывается
   в момент появления. Даже совершенно новый бандл, которого этот скрипт ещё
   не видел, не сможет показать рекламу.

```powershell
node .\desktop\patch-freebuff-ads.js           # patch (backs up first)
node .\desktop\patch-freebuff-ads.js --sound "C:\...\my.mp3"   # patch + custom completion sound (wav/mp3/ogg/flac/m4a/aac)
node .\desktop\patch-freebuff-ads.js --scan    # what ad markers does THIS build carry?
node .\desktop\patch-freebuff-ads.js --verify
node .\desktop\patch-freebuff-ads.js --revert
```

Он запускается автоматически в составе `install.ps1 -Target freebuff`, и его
нужно перезапускать после каждого обновления FreeBuff (обновления возвращают
штатные файлы). Если сборка меняет форму, скрипт называет таргет, который
больше не совпал, — запустите `--scan`, чтобы увидеть, что новая сборка всё
ещё несёт, и обновите там строки.

**Звук завершения FreeBuff.** Рендерер играет `chime-<hash>.mp3`, когда диалог
завершается. Патч находит его тем же способом, что и бандл (имя содержит хеш
сборки), поэтому `--sound <file>` ставит вашу собственную аудиодорожку
(wav/mp3/ogg/flac/m4a/aac) поверх него и оставляет штатный файл как
`chime-*.mp3.bak`; `--revert` возвращает его. `--verify` сообщает, какой из
них активен.

### Кнопка звука FreeBuff (GUI)

`WintageInstaller.ps1` имеет маленькую кнопку **FB ЗВУК** под стеком ПРИМЕНИТЬ
/ ОТКАТИТЬ. Она хранит только *предпочтение*; `install.ps1 -Target freebuff`
читает тот же файл и передаёт его патчу как `--sound`, так что реклама и звук
применяются за один запуск:

- **Левый клик** — выберите аудиофайл (OpenFileDialog,
  wav/mp3/ogg/flac/m4a/aac) и сразу услышьте его: PCM WAV через
  System.Media.SoundPlayer, любой другой формат — через WPF MediaPlayer
  (Media Foundation, асинхронно, поэтому окно никогда не замирает). Выбор
  запоминается в `%APPDATA%\Wintage\freebuff-sound.txt` (на машину, вне
  git-чекаута, ровно как запомненные папки исходных деревьев).
- **Правый клик** — сбросить предпочтение обратно к штатному звуку FreeBuff
  (также останавливает предпросмотр, если он ещё играет).
- **КОПИРОВАТЬ** — копирует выбранное аудио в сам репозиторий
  (`sounds\freebuff.<ext>`, сохраняя исходное расширение) и перенаправляет
  предпочтение на эту копию, чтобы звук пережил удаление или перенос исходного
  файла. Активна только пока задан пользовательский звук; повторное
  копирование просто перезаписывает копию в репозитории. Папка `sounds/` —
  обычное git-отслеживаемое содержимое, так что коммит переживает и повторные
  клоны.

Распознаются только известные аудиоконтейнеры — заголовок проверяется заранее,
поэтому выбор не-аудио объявляется, а не молча проигрывает ничего.

Кнопка показывает `ON`, пока задан пользовательский звук; наведение показывает
путь. Примените таргет `freebuff` после этого (отметьте FreeBuff + ПРИМЕНИТЬ,
или запустите `install.ps1 -Target freebuff` из терминала), чтобы он вступил
в силу.

### Терминалы

`terminal` пишет цветовую схему `Wintage` в каждый обнаруженный стабильный,
Preview или распакованный файл настроек Windows Terminal и выбирает её через
`profiles.defaults`, вместе с консольно-безопасным Consolas 12 и текстом без
сглаживания. Оригинальный файл хранится байт-в-байт рядом, и `-Revert`
восстанавливает его.

`conhost` покрывает классические `cmd.exe`, Windows PowerShell, консольные
профили Git CMD/Bash и другие существующие дочерние ключи `HKCU\Console`. Он
пишет полную 16-цветную таблицу палитры и в корневые значения по умолчанию,
и в каждое существующее переопределение, а затем восстанавливает только те
значения, которые трогал. Consolas применяется и здесь, потому что
пропорциональная Verdana конфликтует с фиксированной сеткой ячеек, которую
используют оба терминальных хоста.

### Браузеры и Tampermonkey

`browsers` находит профили Chrome, Edge, Brave, Cent, Vivaldi и Opera в
установленных местах и в портативном корне, на который вы его указываете
(`-PortableRoot` или запомненная запись `portable` в `paths.json`). Его статус
показывает и число профилей, и сколько из них содержат Tampermonkey. ПРИМЕНИТЬ
копирует выбранную тему браузера в стабильную папку
`%LOCALAPPDATA%\Wintage\browser-theme`, кладёт этот путь в буфер обмена и
открывает каждый конкретный профиль на `chrome://extensions` плюс страницу
Install/Update юзерскрипта Wintage. Профили без Tampermonkey получают и его
страницу в Chrome Web Store.

Chromium намеренно запрещает тихую установку расширений не из магазина на
неуправляемой Windows-машине. Поэтому первая установка темы браузера требует
одного подтверждения **Developer mode → Load unpacked** на профиль. Выберите
скопированный путь; после этого Wintage продолжает заменять ту же стабильную
папку при смене палитр. Подтвердите также **Install/Update** в Tampermonkey.
Никакие файлы `Preferences`, Secure Preferences или LevelDB Tampermonkey не
редактируются за спиной браузера. Если Tampermonkey не было — установите его
с открытой вкладки магазина и обновите уже открытую вкладку `wintage.user.js`,
чтобы получить экран установки.

### Windows

`windows` устанавливает и немедленно активирует контентно-адресуемый
`%LOCALAPPDATA%\Microsoft\Windows\Themes\Wintage-<hash>.theme`. Он стартует с
активной темы и заменяет только документированные секции цвета, курсоров и
визуального стиля. Обои, звуки и значки рабочего стола остаются неизменными;
курсоры намеренно переключаются на установленную схему `___CURRENT___`. Первая
активная тема сохраняется байт-в-байт как `Wintage.original.theme`; смены
палитры сохраняют этот базис, а `-Revert` снова активирует его. Современные
элементы управления Windows всё ещё приходят из подписанного визуального стиля
Aero — Wintage меняет поддерживаемые им тёмный режим, акцент и классические
системные цвета, а не заменяет защищённые `.msstyles`-файлы. Активные и
неактивные заголовки окон разделяют приглушённый цвет приподнятой поверхности
палитры; яркая подсветка остаётся зарезервирована для границ текста/выделения.
Прежний акцент неактивного заголовка снапшотится отдельно и восстанавливается
точно при `-Revert`. Контентный хеш даёт Windows новую цель ассоциации файлов
при пересборке той же палитры, поэтому повторное применение обновлённой
палитры не принимается за бездействие; замещённый файл Wintage удаляется после
того, как Windows подтвердит новый активным.

### OBS Studio

`obs` генерирует вариант OBS 30.2+ поверх поддерживаемой базы Yami Classic,
устанавливает его в `%APPDATA%\obs-studio\themes` и пишет его стабильный ID
темы в `user.ini`, так что выбранная палитра Wintage уже выбрана при следующем
запуске. Закройте OBS перед ПРИМЕНИТЬ или ОТКАТИТЬ: OBS перезаписывает
`user.ini` при выходе. Первое применение резервирует и предыдущий выбор,
и любую тему с тем же именем байт-в-байт.

### Electron-приложения

`resources/app.asar` перемещается в `resources/app/app.asar` (его сосед
`app.asar.unpacked` переезжает вместе с ним — эта пара связана по имени файла,
и её разделение ломает каждый нативный модуль), а маленький `shim.cjs`
занимает освободившееся место `resources/app`. Шим внедряет таблицу стилей,
а затем загружает оригинальный архив. **Ни один байт приложения не
переписывается**, только перемещается; `-Revert` возвращает его обратно.

Таблица стилей для этих приложений не пишется заново — она извлекается из
`wintage.user.js`, так что каждая правка фасок, скроллбаров и типографической
лестницы, сделанная для браузера, попадает и сюда, без второй копии, которая
может протухнуть.

Две заметки, которые стоит знать заранее:

- Очевидный подход — положить `resources/app` рядом с архивом и надеяться, что
  Electron предпочтёт его, — **не работает и молча проваливается**. Electron
  ищет `app.asar` первым. Приложение стартует отлично, и тема никогда не
  запускается.
- Шим — намеренно `.cjs`, а не `.js`. Его `package.json` копируется из
  собственного файла приложения, чтобы приложение сохранило имя и версию (имя
  решает, где живёт userData, — шим, который его переименует, уведёт приложение
  в пустой профиль). Если этот манифест объявляет `"type": "module"`, шим
  `.js` умирает на первом же `require`.

### Десктопное приложение Claude: на месте, и фрейм, в котором оно реально рисует

Claude не может использовать перемещение выше, потому что
`OnlyLoadAppFromAsar` включён намертво, — Electron загружает
`resources/app.asar` и ничего больше, поэтому шим в `resources/app` никогда не
запустится. Вместо этого он патчится **на месте**: архив резервируется, его
`main` в `package.json` переписывается на `"../wintage-shim.cjs"` (дополняется
до той же длины в байтах, чтобы каждый офсет в архиве оставался валидным),
и пер-файловый хеш целостности обновляется под совпадение. `-Revert`
восстанавливает резервную копию.

Установщик всё ещё читает фьюзы **до того, как что-либо перемещает**, и
отказывается с причиной, когда они блокируют его, —
`EnableEmbeddedAsarIntegrityValidation` заставил бы переписывание выше падать
при запуске, а не при установке. Проверьте любое приложение сами:

```powershell
node ..\tools\electron-fuses.js "<path to the app's exe>"
```

Вторая половина этой проблемы была куда тише. `BrowserWindow` у Claude рисует
тонкую оболочку, а **всё видимое приложение — это `WebContentsView`**,
прикреплённый к ней. Шим раньше перехватывал `browser-window-created`, поэтому
он внедрял таблицу стилей в оболочку, докладывал об успехе в
`wintage-status.txt` и не менял ничего, что вы могли бы увидеть. Теперь он
перехватывает `web-contents-created`, что покрывает содержимое окон,
`WebContentsView`, `BrowserView`, гостей `<webview>` и попапы одинаково.

### Obsidian

Коммьюнити-тема пишется в `.obsidian/themes/` каждого хранилища — все
шестнадцать палитр сразу, ровно как таргет VS Code, так что вы переключаетесь
между ними в **Settings → Appearance** без перезапуска чего-либо. Шаблон
выведен из ручной темы `VintageWin95`, уже лежащей в хранилище, — каждый цвет
заменён токеном, которому он был равен. `-Palette <slug>` задаёт, какая из них
активна при установке; `appearance.json` сначала резервируется, а `-Revert`
удаляет только темы `Wintage *` и восстанавливает ваш прежний выбор — ручная
тема в том же хранилище не трогается никогда.

### SAIPENVIEW

Его фронтенд уже объявляет имена токенов Wintage в собственном `:root`, поэтому
этот патч переписывает **только значения токенов** — никогда селектор, шрифт,
ширину рамки или паддинг. Ничего, что влияет на боксовую модель, не меняется,
так что текст не может сдвинуться. Это намеренно: ранний подход добавлял всю
браузерную таблицу стилей сверху, а `wintage.css` написан для произвольных
веб-страниц — универсальные селекторы, принудительно задающие шрифт, лестницу
размеров, рамки 2px и высоты контролов. На приложении, у которого уже есть
собственная раскладка, это двигает всё.

Проверено маскированием каждого hex и диффом с резервной копией: структурно
идентично, отличаются только литералы цвета. `--link` сообщается как не
объявленный там (его markdown-ссылки читают `--accentTeal`, который этот патч
задаёт), а не внедряется, — добавлять переменную, которую приложение никогда
не читает, было бы мёртвым грузом.

### MPC-HC (K-Lite)

Нативный Win32, ни таблицы стилей, ни точки внедрения, а цвета его тёмной темы
скомпилированы в программу, — никакое значение реестра их не открывает. Поэтому
этот таргет **не может нести палитру**. Что он делает: включает тёмную тему и
применяет правила типографики из UI.md к OSD — единственной поверхности,
которую MPC-HC даёт пользователю контролировать. Прежние настройки сначала
экспортируются в `desktop/backup/mpc-hc-settings.reg`.

Закройте MPC-HC перед применением: он перезаписывает свои настройки при выходе.

## Пересборка

Всё под `desktop/out/` генерируется из `themes/*.json`. Это не отслеживается
в git (T-160), так что свежий клон должен один раз собрать его перед
установкой:

```powershell
node ..\tools\build-desktop.js          # rebuild all targets
node ..\tools\build-desktop.js --check  # exit 1 if anything is stale
```

`release.ps1` запускает сборку и каждый шлюз, поэтому релиз не может выпустить
вывод, который разошёлся с палитрами.
